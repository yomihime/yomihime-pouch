# 技能维护规范

本文件供本仓库技能作者与维护者使用，不是运行时共享依赖。每个技能单独安装后也必须包含完成自身任务所需的规则、引用、脚本和许可说明；不能要求安装者拥有本文件或其他未声明技能。跨技能协作可在技能可用时引用；缺失时说明并安全降级，不自动安装无关技能。

## 基本结构和版本

- 每个技能目录提供 `SKILL.md`，以 YAML frontmatter 声明与目录一致的 `name`、说明何时使用的 `description`。`metadata.version` 是唯一版本权威，必须为带引号的三段数值语义版本字符串，如 `"1.0.0"`；每段为 `0` 或不以零开头的 1–9 位 ASCII 数字（最大 `999999999`），不接受预发布、构建后缀、缺段、负数、空格或隐式数值。禁止根级 `version` 作为第二版本字段；README、Git tag、时间及文件 mtime 均不能替代该字段。比较时解析为三个整数后逐段比较，不按字符串排序。
- `metadata.updated_at` 单独记录本次实际内容修改的 UTC 时间，格式为带引号且日期时间真实有效的 `"YYYY-MM-DDTHH:MM:SSZ"`。该时间只作信息与审计，永远不决定更新、降级或冲突优先级；修改技能正文、脚本、引用或其他随附内容时同步更新，不伪装未来时间或发布日期。
- 本次 `"1.0.0"` 是供 PR 审阅的候选基线，尚未正式发布；填写版本不等于发布、安装或授权升级。正式发布后，破坏性变更增加主版本、向后兼容能力增加次版本、兼容修复增加修订版本。发布内容相同版本却有不同字节时视为同版漂移，不能用更新时间掩盖；同一候选在发布前的编辑仍需正确记录更新时间。
- 旧 UTC 日期版本不能与数值版本直接比较，也不能仅因改格式覆盖。迁移必须使用经核验来源的显式映射，锚定旧 commit/tag 及完整技能目录摘要，明确对应新基线，并逐文件核对本地新增、删除、修改、执行位和目录。无法证明整个本地目录等于可信旧基线则保留并要求决定；具体的自包含流程及只读辅助工具见 `yomihime-init`。
- 需要时使用简明 `README.md`、`agents/openai.yaml`、`references/`、`scripts/` 和测试；引用使用相对路径，实际安装后仍须可解析。单独许可或第三方来源需在技能目录中保留适用的许可和声明；不得把仓库根许可错误地扩展到有单独许可的目录。
- `SKILL.md` 写清触发范围、步骤、输入、权限、失败处理、验证和交付边界。可执行脚本与说明要一致；变更前检查受影响行为并补充回归测试。示例应标注假设，不把启发式扫描或结构检查误报为语义、视觉或端到端通过。

## 项目工作区

- 项目内技能和 Agent 的规范、记忆、计划、运行记录与临时材料统一放入 `.agent-workspace/`。默认布局：`design/` 存设计/文案指南与按需资源记录；`memory/` 存项目记忆；`architecture/` 仅在无现有有效图源且确有需要时按需保存跨任务架构图纸；`<work-id>/plan.md`、`jobs/`、`pipeline/`、`scratch/` 及 `artifacts.md` 存任务材料；`index.html` 是流水线入口。项目能力记录可放 `runtime.md`。目录按需创建，`design`、`memory`、`architecture` 等保留名不可作为 work-id。固定根文件名 `runtime.md`、`index.html`、`pipeline-index-data.js`、`.pipeline-index.lock` 即使尚未创建也保留，work-id 比较时不区分大小写，尾随点和空格按 Windows 别名处理。
- 该工作区默认是本地协作材料，不自动提交、发布或删除。正式交付物遵循用户指定的位置与授权。`AGENTS.md` 保留在项目既定位置，作为简短入口指向实际有效文档；保护既有内容、隐私和 Git 忽略状态。
- 源码默认在主 checkout，按互不重叠文件分配写入权。`.agent-workspace/` 不放源码 checkout 或 worktree；跨仓库确需 worktree 时仅使用主仓库根目录下可见的单个共享位置。成功交接并接收后回收 Agent，仅在确认授权、引用、占用与恢复条件后清理自建临时材料；保留当前指南、记忆和流水线日志/报告。
- 跨任务架构图纸原位复用现有有效唯一源，不因新默认目录迁移或覆盖。现有权威若为非 JSON 正式材料，先保留并协调唯一权威及获准转换，不能自动降为摘要或旁建第二图源。稳定的 `AGENTS.md` 或 `memory/current.md` 入口登记同一源的路径、修订、现状/目标状态与 owner；current.md 仍直接保留恢复必需概览，不再手工维护同义 project-memory 图源。图源由单一 writer 更新，交接核对入口、修订与接收者；任务/运行清理不得删除仍在使用的图源及引用依据/视图。HTML 等视图为派生物，不取代机器源或成为另一份权威。
- 不建立旧路径的长期兼容或双写。旧项目下次运行 `yomihime-init` 时先只读盘点已有内容和引用，提出可核验的整理方案，再在用户授权和安全条件下处理：禁止覆盖、保留来源与哈希、验证结果，冲突或不确定时停止并询问。流水线事件格式兼容不等于旧目录仍是运行入口。

## 初始化与发布检查

`yomihime-init` 先检查上游 GitHub 连通性，再盘点所需技能；离线且缺失不可继续，离线且所需技能均可用则警告并继续，清单无法确认时不得宣称完整。在线比较版本时无版本标记或非法版本是未知而非缺失；只按合法数值版本或显式可信旧版映射判定候选，在来源可信、完整目录本地修改核验清楚且权限允许时安全更新，保留本地定制，失败可恢复。更新时间不参与排序。具体流程在该技能中自包含。

修改后检查路径和链接、元数据解析、相关脚本与测试，复核真实运行范围、隐私和授权；版本更新、发布或安装必须区分。完成时说明基准、验证结果与未验证项，不以通过文档检查代替运行时行为验证。
