# 当前切片的实施交接

图纸应消除关键语义的猜测，不需要复制函数实现或为每个字段写百科。接手者可以顺着一个入口完成一次正常流程，知道每个失败出口如何处理，并用给定样例验收。只对当前切片及其直接依赖达到这个深度。

## 交接前检查

- **范围与定位**：改哪些模块/路径、哪些不改；从哪个入口开始；依据哪个代码候选、图纸修订和有效决定；写入权由谁持有。
- **接口**：调用者、所有者、调用方向、同步/异步和副作用；输入/输出的名称、类型、必填、空值、边界值、单位、格式及默认行为。仅写 `object` 或“返回结果”通常不足以开工。
- **规则**：校验顺序、鉴权/信任边界、去重或幂等、排序、并发、事务和持久化边界。仅补本切片相关要求，不凭空引入复杂协议。
- **错误**：具体错误码或失败类型、触发条件、是否有副作用、调用者可见输出和恢复行为；超时/重试/取消只在实际涉及时定义，不默许无限重试。
- **状态**：初始状态、允许的 from/to/trigger、终态、失败后保留/回滚什么。没有状态转换的接口可以不写，不能用空数组掩盖真实状态未决。
- **流程**：入口、校验、关键调用、成功出口、失败出口、恢复分支；每一步指向实际元素和契约，转移条件互相不矛盾。并发或循环的终止/收敛条件写清楚。
- **验收**：具体输入、预置条件、可观察输出/错误和副作用；至少覆盖本切片的主要正常路径及关键边界/失败。每条有执行入口或预期验证方法，不能只有“功能正常”。
- **未决项**：哪些假设不阻碍这轮、哪些必须先确认、由谁处理。缺少决定时阻塞对应步骤，不让较弱执行模型补出产品规则。

## 写入规范源的对应位置

调用关系放 `relationships`，职责放 `elements.responsibilities`，约束放对象 `rules` 或参数 `constraints`；跨模块协议统一放 `contracts`，由元素、关系和流程步骤以 `contractIds` 引用。输入/输出放 `inputs`/`outputs`；失败条件与恢复放 `errors`；状态转换放 `stateTransitions`；可运行的示例数据放 `examples`。具体执行顺序使用 `flows.steps` 与 `flows.transitions`，本轮验收放 `changes.acceptance`。

标准字段不表达的有用信息先用现有描述说明，确需结构化扩展再用 `extensions` 命名空间；不要随意新增拼写近似字段，让严格校验失效。目录、状态等完整约束以 [结构规范](source-contract.md) 和 Schema 为准。

## 深度示例：创建一次作业

这是**假设性写法示范**，不是另一个可执行真源，也不规定项目必须有作业系统：

- 含糊：“校验后创建任务，失败时处理错误。”
- 可实施：“`createJob` 接收非空 `requestId` 字符串与待处理项目列表；先校验项目数，再查询 requestId。相同 requestId 与相同规范化输入返回同一 jobId；相同 requestId 但输入不同返回 CONFLICT，不写新记录。创建记录成功后返回 jobId 和 queued；存储失败返回 STORAGE_UNAVAILABLE，保留原数据，不在本接口自动重试。”
- 状态：“not-created 在持久化成功后进入 queued；输入错误保持 not-created。是否允许取消及取消后的状态未知，本轮不实现取消入口。”
- 验收：“首次请求得到一个 queued 记录；相同请求重放返回原 jobId 且总记录数不变；更改输入并复用 requestId 得到 CONFLICT 且无新记录；模拟存储失败后无半成品记录。”

这些规则必须来自用户要求、已有行为或被接收的技术决定；不能为了显得详细擅自发明。将这种深度填入真实 JSON 后，渲染出的契约和流程应能直接供实现者阅读。

## 不把设计验收当作运行验收

JSON 通过校验只表示结构/引用合规；页面可打开只表示渲染可用；`planned` 仍未实现。实现者必须用实际代码候选与测试/运行证据回报。只有有证据的行为才可标 current，只有对应验收确实通过才可标 verified；失败、跳过、未运行分别保留。最终报告说明本轮哪些视角和行为已覆盖、哪些不在范围。
