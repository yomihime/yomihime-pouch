# yomihime init / 项目工作环境初始化

本技能的规范标识是 `yomihime-init`。通过当前宿主支持的 Skill 调用方式使用它（例如 Codex 中可用 `$yomihime-init`）；这不是已安装的 shell 命令，不假定所有宿主采用相同语法。

初始化的是 **技能与 Agent 工作环境**。本技能不实现需求，不改业务源码、测试、依赖、构建配置、数据库或产品行为，不提交、推送、安装应用或发布。技能更新、项目私有工作材料与获准的简短指导入口属于初始化范围；不能借此执行下载脚本或扩大权限。

本技能是供 Agent 执行的指导，不自带联网程序或自动安装器。附带的可选 Python 辅助工具将纯版本值比较与完整目录校验分开；只有目录校验路径可输出候选建议，纯值比较不判断安装资格。工具不下载、更新、迁移或执行其他技能。实际执行时由使用该技能的 Agent 使用其可用工具检查 GitHub、盘点并按权限处理更新；检查本技能本身时核对链接和指令语义即可，不把联网端到端运行作为技能有效性的前提。

## 触发示例与运行要求

- 使用："检查技能更新并初始化这个项目的 Agent 工作区"；"先盘点旧工作材料，按授权安全整理"。
- 不使用："实现登录功能"；"安装项目依赖并发布"；"只解释 Git 如何工作"。初始化工作环境不授权产品开发、应用安装或发布。
- 主流程不要求 Python、Node.js 或特定操作系统；可选 [版本辅助工具](scripts/version_advisory.py) 使用 Python 3.10+ 标准库；纯值比较不依赖 POSIX，目录校验另需 POSIX 安全目录读取能力。无所需能力时按同一协议人工核对，不为此安装依赖。需要宿主提供 GitHub 只读连接器或获准的 Git/HTTP 工具，以及本地文件读取与获准写入能力；不强制安装 Git 命令行工具。真实安装目录与加载规则依客户端核实，源不可核验时遵循下文离线分支，不声称已完成跨平台或联网端到端验证。

## 可用脚本 / Available Scripts

| 脚本与入口 | 输入与用途 | 输出及边界 |
| --- | --- | --- |
| [version_advisory.py](scripts/version_advisory.py) `versions` | 本地/候选版本字符串；跨平台纯数值比较 | JSON 数值关系；不读目录、不核验内容/来源、不判断安装资格 |
| 同一脚本 `inspect` | 一个已确认范围的技能目录，读取版本及完整内容摘要 | JSON 清单与指纹；不写文件、不验证来源真实性 |
| 同一脚本 `compare` | 本地目录、固定候选目录，以及按需提供的可信基线或旧版映射开关 | JSON `decision` 与理由；仅给建议，不下载、安装或授权覆盖 |

纯值示例：`python3 scripts/version_advisory.py versions --local 1.9.9 --candidate 1.10.0`。完整参数、退出码与信任前提见 [辅助工具说明](references/skill-sync.md#可选只读辅助工具)。纯值比较不读取目录、不判定安装资格；目录检查在原生 Windows 或缺少 POSIX no-follow 能力时退出码 2，报告 unknown 并交人工核验，不作不安全回退。不把纯值比较或人工检查称为安全迁移实测。

## 执行顺序

严格按 **GitHub 源检查 → 本地技能盘点 → 版本与安全更新 → 工作区初始化及旧材料整理 → 回读与报告** 进行。读取适用的指导和确认项目位置不算技能盘点；源检查完成或明确失败前，不先扫本地技能或创建项目文件。

### 1. 检查技能源

- 默认源为 `https://github.com/yomihime/yomihime-pouch` 的 `main` 分支下 `skills/`。用户明确指定其他可信源时记录该选择；不把目标项目自己的 `origin` 当作技能源。
- 优先用现有 GitHub 连接器或已经获准的只读 Git/HTTP 访问。获取该仓库 `main` 的具体 commit SHA 和 `skills/` 目录，才算源可达；GitHub 首页可访问、缓存命中或其他仓库连通都不算。
- 固定本次 SHA。该 SHA 下每个 `skills/<name>/SKILL.md` 构成远端技能目录；读取版本后，实际下载也固定该 SHA，不混用变化中的 `main`。不执行仓库内容。
- 区分连接超时、DNS/网络问题、无访问权限、认证失败和源内容损坏；保留不含凭据的简短证据。没有适用工具也是「源不可核验」，不能冒充网络断开。不要为检查改网络设置或创建凭据。

### 2. 盘点实际技能

按 [版本、清单与更新协议](references/skill-sync.md) 确认需要的技能集合、真实安装位置、加载优先级和内容。只读本任务相关路径，不全盘搜用户目录。

- 区分源码仓库副本、真正可加载的安装副本、缓存和备份。不得因当前仓库有 `skills/` 就声称运行时已安装；同名多份列出实际生效者及遮蔽关系，无法判断时停在需要确认。
- 「可用」至少要求目录可读、`SKILL.md` 可解析、名称与目录对应、正文非空，以及本次流程必需的相对资源存在且可读。内容存在但损坏不算可用。版本缺失或格式无效记为 `unknown`，**不是缺失**。
- 需要的技能集合来自用户范围、可信目录或此前核验的清单，不能拿「本地恰好安装的几个」反推应有集合。缺少完整性依据时如实报告，不把仅有本技能当作整套就绪。

| 源状态 | 所需本地技能 | 结果 |
| --- | --- | --- |
| 不可达或不可核验 | 任一所需技能缺失或不可用 | **失败**，列出缺项；不进行后续初始化、更新或迁移 |
| 不可达或不可核验 | 全部可用 | **警告后继续**；明确没有核验最新版本，保留未知版本 |
| 可达，目录完整 | 有缺项 | 从固定 SHA 准备补齐，安全验证与必要授权后安装；仍有缺项则失败 |
| 可达，目录完整 | 全部可用 | 按整数三元组比较数值版本；旧日期版本另走可信映射；候选通过安全协议才更新 |
| 可达但目录不完整/损坏 | 无法证明整套所需内容 | 不宣称在线核验通过；用可信旧清单重新判断本地完整性，能降级继续则警告，否则失败 |

只检查连通性与库存的失败路径不写项目文件。离线情况下不删除现有副本，也不为填补缺项编造替代技能。

### 3. 比较与更新

版本唯一取 `SKILL.md` frontmatter 的 `metadata.version`，格式为带引号的三段数值语义版本 `"MAJOR.MINOR.PATCH"`，例如 `"1.0.0"`。每段为 `0` 或不以零开头的 1–9 位 ASCII 数字；拒绝预发布/构建后缀、缺段、空格和隐式数值。解析成三个整数比较，例如 `1.10.0 > 1.9.9`，不按字符串、日期或根级 `version` 排序。

`metadata.updated_at` 单独记录实际内容修改时间，必须为合法的带引号 UTC `"YYYY-MM-DDTHH:MM:SSZ"`。它是审计信息，永不决定更新顺序；同版本只改更新时间仍是内容漂移，不能当升级。当前 `1.0.0` 是待审候选，不代表已正式发布、安装或获准更新。

旧 `metadata.version` 若为 ISO 日期，属于 **legacy 待映射**，不能当较小版本、零版本或自动改成 `1.0.0`。仅在可信映射明确连接旧源与新基线、完整本地目录与旧源完全相同、目标固定 SHA 来源核验且授权具备时准备迁移。随附 [旧版映射](scripts/legacy-version-map.json) 锚定 `a890a0b69e7f518922591cc42e39d91f9b2a99ec` 的八个完整技能源目录到本次 `1.0.0` 候选；其他旧来源、同日期异内容、本地定制或未知项一律保留并报告。映射不是发布凭证，也不允许忽略完整目录差异。

- 远端数值版本较新或明确旧版映射成立：先确认本地完整目录与可信基线一致、准备完整技能目录、验证、备份、替换并回读。更新整个技能而非仅 `SKILL.md`，含必要 scripts、references、assets 和 UI 元数据。
- 版本相同且完整目录相同：不重复更新；任何内容、文件增删、执行位或目录不同则报告漂移，不能视为无事发生或自动覆盖。
- 本地数值版本较新：保留，不自动降级。任一版本未知或旧日期版本无匹配可信映射：保留并报告，不能猜测新旧。
- 版本较旧不代表本地内容可丢弃。无法证明本地与已知来源一致，或有本地改动、冲突、权限不足时，保留原件，列出目标及差异并获取所需决定。不得 `git reset --hard`、`git clean` 或粗暴覆盖安装目录。
- 本次已获准的正常干净升级无需反复询问。用户请求和执行环境的安装、运行及文件权限要求仍适用；查看或下载不自动授权运行新脚本。

完整流程见 [安全更新](references/skill-sync.md)。更新失败时优先保持或恢复核验过的原副本，重新判断可用性；不把「发现更新」「下载完成」或「替换失败」报告成已更新。正在执行的 `yomihime-init` 若自身有新版，先暂存，最后完成替换和验证，不在半次执行中切换流程；当前会话仍按已经加载的版本完成，说明新版本何时由运行时重新加载。

### 4. 建立统一工作区，整理旧材料

仅在所需技能可用且获准继续后执行。先读取 [迁移与防损协议](references/workspace-migration.md)。一律以 `.agent-workspace/` 为新的项目本地工作区，按需创建，不批量铺空模板：

```text
.agent-workspace/
├── memory/                  # current.md、references/、evidence/、archive/
├── architecture/            # 按需稳定架构源，跨任务复用；已有有效源原位保留
├── design/                  # ui-guide.md、writing-guide.md、resources.md，按需
├── plans/                   # 独立计划文档，按需
├── work/                    # 无专用归属的临时材料，按需
├── runtime.md               # 已核验的运行环境和能力，按需
├── index.html               # 流水线工具生成的项目索引，按需
├── pipeline-index-data.js   # 流水线工具生成的索引数据
├── .pipeline-index.lock     # 流水线工具生成的索引锁文件
└── <work-id>/
    ├── plan.md
    ├── scratch/
    ├── jobs/
    ├── pipeline/
    ├── artifacts.md
    └── init/                # 本次盘点、迁移映射、技能来源与更新回执，按需
        ├── staging/         # 候选暂存，按需
        └── backups/         # 恢复依据，按需保留
```

`<work-id>` 不得占用 `memory`、`architecture`、`design`、`plans`、`work` 或已有工具保留名称。固定根文件名 `runtime.md`、`index.html`、`pipeline-index-data.js`、`.pipeline-index.lock` 即使尚未创建也保留，比较时不区分大小写，尾随点和空格按 Windows 别名处理。init 可使用 `init-<UTC时间>` 加必要防冲突后缀，不复用他人正在写入的目录。

- `.local-dev/`、`.local_dev/`、`.project-memory/`、`.agent-work/` 等只在本次迁移审计时识别，不设目录搜索回退、别名、软链接或双写；新建材料使用新结构。有效入口已明确指向既有架构权威源时，继续原位使用该源不属于旧目录 fallback；未获迁移授权前保留其实际入口与使用，不旁建默认源或仅因路径旧而阻断读取。
- 旧项目不套固定模板。结合实际入口、用途、引用和占用逐项判断，记录「原路径 → 新路径、依据、校验、未决项」。只整理确认为 Agent 工作材料、计划、记忆或规范的文件，不按目录名猜测可移动或可删除。
- 整理不等于丢弃。已有内容、用户改动、旧记忆历史与证据须保留；目标冲突、未知归属、正在使用或依赖源码路径的文件先保留并报告。需要修改项目代码才能迁移的项留待另一个明确授权的任务，不能在 init 内改代码。
- 架构源先按有效入口核对路径、范围、修订和 writer。采用 architecture-design 且没有有效源时，才按需使用 `.agent-workspace/architecture/architecture.json`；已有有效源原位复用，不因新任务或目录模板复制、转换或搬迁。迁移或覆盖源、调整权威入口须明确授权并核验恢复与引用。JSON 确认为同范围唯一详细机器源后，`memory/references/architecture.md` 保留有证据的现状说明和源引用，不复制契约；已有权威 Markdown 未经获准转换不能自动降级。任务结果只保留建议、差异和报告，活跃源与必要图纸依据不属于普通临时清理。
- 仓库根 `AGENTS.md` 保留为运行时入口，不搬进隐藏目录。经授权仅更新与迁移有关的简短链接及读取规则，保留其他指导。源码 checkout、worktree 与真实业务数据不放进此工作区。
- 默认本地私有。写入前检查 tracked/staged/ignore 状态，按授权精确维护本地 exclude，不修改共享 `.gitignore`、全局设置或用户暂存区。已跟踪的私有材料保留原状并报告，不靠 ignore 假装解决泄露风险。

需要新记忆时交 `project-memory`，需要新架构源时可交 `architecture-design`，需要设计或文案指南时交相应技能；缺少对应技能时保留既有资料并报告，不能凭 init 编造已转换或已验证的结果。只初始化与本次工作有关的最小内容，未知标明未知，不为 init 强制启动完整开发流水线、全仓测绘或重建所有规范。

### 5. 验证与交付

回读实际安装副本与工作区入口；核对新旧内容校验、引用、未决冲突和隐私。再次执行应保持无变化，不重复搬迁、覆盖、备份或制造新权威副本；只有实质变更才新增更新/迁移记录。

报告以下信息，必要时附本地报告路径：

- `ready` / `ready_with_warnings` / `needs_confirmation` / `failed`；后两项列出未完成动作，不冒充已完成。
- 技能源和固定 SHA、连通性结果；应有/可用/缺失技能与未知版本。
- 各技能原版本、目标版本、实际动作和验证结果；待更新不等于已更新。
- `.agent-workspace/` 已初始化/迁移的内容，原件或备份去向、冲突、未执行项及下一步。
- 项目源码未改，实际涉及的技能与本地工作文件范围；检查发现已有源码改动时注明它们原已存在，不回滚。

执行 Agent 按本次真实操作核对适用条件与结果；技能维护者如需模拟验证，可参考 [验收场景](references/acceptance-cases.md)，这不是每次初始化的前置步骤。文件或说明存在只证明材料存在；没有实际执行更新、迁移或验证时，不能声称它们已完成。
