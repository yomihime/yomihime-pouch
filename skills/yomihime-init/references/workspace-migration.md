# 工作区初始化与一次性迁移

## 范围与只读基线

开始时先核对真实项目根、有效 AGENTS/override、当前 staged/unstaged/untracked 状态和必要的文件权限。基线用于分辨既有改动，不修改、暂存或回滚它们。迁移只整理经证实的 Agent 材料，不做产品代码迁移，也不引入长期兼容层。

先检查 `.agent-workspace/` 及其父路径不是意外 symlink、嵌套仓库或别的项目的工作区。已存在时保留内容，按需补充；不能先清空再初始化。使用唯一 work-id，不和其他任务争同一个 writer 或目录。

默认本地私有：读取 Git 对这些路径的 tracked/staged/ignore 状态。在授权范围内用 `git rev-parse --git-path info/exclude` 找到该工作区真实的本地 exclude，精确添加项目根 `.agent-workspace/` 的匹配项并验证忽略结果，不盲写一个猜测的 `.git/info/exclude`。不动共享 `.gitignore`、全局规则或用户暂存区，不擅自改变文件的已跟踪状态；获准的简短入口更新仍按下述范围执行。非 Git 项目则说明无法提供 Git 忽略保障，不伪造检查通过。

已跟踪/暂存的私有材料不会因 exclude 生效而停止共享；记录为需要处理的风险，未经授权不删除、untrack、重写历史或发布。存放记录前处理秘密与个人数据边界；不输出秘密值，也不以「备份」为名复制不获准传输或复制的数据。

## 定向审计

仅检查已知存在的旧目录及适用入口实际指向的材料，包括 `.local-dev/`、`.local_dev/`、`.project-memory/`、`.agent-work/`。它们只作为迁移来源，日常 skill 不再搜索或回退到它们。其他旧项目目录通过实际引用与内容识别，不全盘搜索或按名称批量重命名。

对每个拟处理项记录相对路径、用途/所有权证据、摘要、引用方、占用情况和建议目标。目标按实际内容而不是旧目录名决定，例如：

| 经证实的材料 | 新位置 |
| --- | --- |
| 项目完整当前快照和其关联 references/evidence/archive | `.agent-workspace/memory/`，保留原历史与关系 |
| 当前有效 UI/文案/资源规范 | `.agent-workspace/design/` 对应文件 |
| 独立计划文档 | `.agent-workspace/plans/` |
| 具体任务的 plan.md、jobs、pipeline、scratch、产物清单 | 对应 `.agent-workspace/<work-id>/` |
| 无专用归属的普通临时材料 | 经确认后 `.agent-workspace/work/` |
| 未知文件、真实数据、源码、checkout/worktree、被代码依赖的路径 | 不自动迁移，报告具体阻塞 |

发现旧目录同时混有多个用途时逐项映射，不把整个目录直接挪进某个新子目录。原目录内含不应迁移的文件时保留它，不为「整洁」丢文件。多个当前快照或指南冲突须结合来源和日期核验，不能仅按 mtime 选一个覆盖；无法确定唯一现状时询问。

## 可恢复整理流程

1. 将拟迁移的映射与冲突保存在 `.agent-workspace/<work-id>/init/`，列出已经授权和需要额外确认的项。当前明确请求 init/整理涵盖的常规工作文件可推进；用途不明、数据/秘密、覆盖、删除或跨范围改动不由推断补充授权。
2. 确认没有写入进程、活动 Agent、观察器、构建或文件锁依赖来源路径。不能确认就保留并报告。不能为搬文件自动停止用户进程。
3. 为获准迁移准备原始内容清单和恢复路径。流水线索引发现规范位置的运行，因此不要把 journal 备份放到会被发现为运行的位置；可在 `init/backups/` 保存经过解包回读与摘要校验的归档包，并以明确索引记录包内路径，不能仅改 journal 文件名后宣称仍可直接恢复。已存在的目的文件不得直接覆盖：相同内容也先记录去重依据，不自行删除原件；不同内容分别保留为有来源标记的待合并候选，不将候选冒充当前权威版本。
4. 用能保留完整内容与必要元数据的方式迁移到新位置，回读并比对文件数、相对路径、字节摘要及必要权限。跨文件系统或不保证原子的操作先复制、校验，再在允许移除来源时处理原件；不要用 `mv` 的退出码代替内容校验。
5. 对可改的工作材料与获准入口局部更新引用。根 `AGENTS.md` 仍在原位，其他有效指导保留。所有长期证据与历史引用必须可解析：可在历史之外保留原路径到归档位置的迁移索引，历史原文不为美化批量重写。不建立旧路径软链接/别名或双写机制。
6. 检查入口、规范、记忆、流水线产物与相对链接。运行中的流水线先停止依赖该目录的活动或等待交接；已有 journal/生成器若保存旧绝对路径，查其支持的迁移/重建方式，不靠字符串替换改候选身份、事件证据或历史。原始事件中的绝对证据路径没有受支持的解析/迁移机制时，迁移索引只能帮助人工恢复，不能让工具自动找到证据；保留其来源路径，不宣称已迁移完成。无法在不改项目代码/不破坏证据下完成就保留该项并报告。
7. 只有目标完整、引用修复、恢复副本/映射有效、无占用且移除原件已获准时，才能移除旧位置。用户没有授权删除时保留原件并报告未收束，不宣称已经迁移完毕。归档默认保留，不因 init 自动清理。
8. 回读最终状态并与只读基线核对，确认本次没有修改项目源码、依赖或暂存区。已有用户改动保持原样。重复运行从回执和实际目标核验，无新变化不再搬文件或生成重复备份。

## 完成与部分完成

- **已完成**：新位置唯一生效，内容与引用核验通过，原件去向及恢复路径明确，无未处理的关键冲突。
- **带警告可继续**：本次工作需要的环境已就绪，另有不影响当前工作的旧材料原样保留；列出残留及原因，不把它们视为兼容运行目录。
- **需要确认/失败**：关键材料冲突、必要引用无法迁移、未知权限或有潜在数据损失。停止受影响动作，继续不依赖它的已授权只读检查；结果不能标为整套完成。

不为了把所有目录都移走而修改项目代码、删除证据或隐瞒未决项。旧项目的一次性整理可以分阶段完成；新工作只写新结构，遗留项是待处理事实，不是需要永久维护的兼容功能。
