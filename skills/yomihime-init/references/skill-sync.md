# 技能清单、版本与安全更新

## 确定需要的集合

不要硬编码「当前安装了哪些技能」或只检查自己。按本次范围确定集合：

1. 用户明确指定的技能集合优先，包含本次操作确实需要的依赖。
2. 默认整套 init：在线时从本次固定 commit 的 `skills/*/SKILL.md` 推导目录；离线时使用此前核验的整套目录回执，或用户确认的可信本地源码 checkout 的同级技能目录。回执须标明来源、范围与源 commit，不能用任意缓存文件冒充目录。
3. 没有可信所需目录时，无法证明全套完整：停止完整初始化并说明缺少什么。若用户明确选择较小范围，可只检查该范围；不能自行把要求缩小为本地恰好存在的技能。

目录中的 skill name、相对路径和版本均取实际文件，不从 README 表格或文件夹数量推断。忽略不含 `SKILL.md` 的普通文档目录，不忽略损坏的候选技能。

## 有效安装与盘点回执

确认当前运行时实际支持的技能目录与加载规则。项目级 `.agents/skills/`、用户级 `$CODEX_HOME/skills/` 等只是候选示例，须按环境核验，不能机械写死。安装到获准且会生效的位置；不改全局配置来让它生效，不把项目工作区中的暂存副本当作安装成功。

每个所需技能记录：

- name、有效路径、其他同名副本、可用/缺失/损坏及原因。
- 本地/远端唯一版本字段 `metadata.version`，以及独立的 `metadata.updated_at`。版本无法解析时为 `unknown`，旧 ISO 日期单独记 `legacy` 待映射；保留原字段供诊断但不执行内容。更新时间永不参与更新顺序。
- 必需资源是否存在，来源 commit、已知基线与内容摘要是否可验证。
- 拟执行动作、权限、结果和需重新加载的运行时限制。

校验是静态检查，不为证明技能可用而运行其中的安装器、任意 shell、依赖脚本或产品操作。若确需执行验证脚本，按已有信任及本次授权单独判断。

## 数值版本的判定

`metadata.version` 是唯一版本权威，必须是带引号的三段数值字符串 `"MAJOR.MINOR.PATCH"`。每段为 `0` 或不以零开头的 1–9 位 ASCII 数字（`0` 至 `999999999`），如 `"1.0.0"`、`"1.10.3"`。拒绝前缀 `v`、前导零、负号、缺段、空格、Unicode 数字、预发布及构建后缀；先限制格式和长度，再解析为整数三元组按顺序比较。`1.10.0` 大于 `1.9.9`，不能按文本字典序比较。根级 `version` 禁止作为第二版本字段；存在时报告冲突并拒绝自动判断；重复或歧义的元数据一律停止自动判断。

`metadata.updated_at` 是独立的实际修改时间，要求带引号的、真实存在的 UTC `YYYY-MM-DDTHH:MM:SSZ`，包括有效日历日期和秒。不接受其他时区或仅日期；缺失/非法时报告元数据问题，待安装候选必须修正，但不能把它变成版本、零版本或排序依据。本地更新时间异常不改变已合法解析的数值版本大小。文件 mtime、下载时间和 commit 时间也不决定版本。

当前 `1.0.0` 是 PR 待审候选，不是已经发布的声明。目标内容仍须来自本次核验过的固定 SHA；仅出现版本号、`updated_at` 或 Git tag 名称不能证明来源可信，也不授权安装。

| 本地/远端情况 | 动作 |
| --- | --- |
| 本地缺失，远端合法完整 | 准备新安装，验证与必要授权完成后生效 |
| 两者合法，远端整数三元组较大 | 候选升级，继续检查完整本地目录是否等于可信原基线及权限 |
| 两者合法且版本相同，完整目录一致 | 无需修改 |
| 两者合法且版本相同，完整目录不同 | 同版漂移；包括仅更新时间不同，保留本地，不覆盖 |
| 两者合法，本地整数三元组较大 | 保留本地，提示领先于源；不降级 |
| 本地 ISO 日期版本、远端数值版本 | 不作跨格式排序；只按下述显式可信映射准备迁移 |
| 任一版本 unknown，或旧版无匹配映射 | 报告无法比较并保留；需要替换时明确询问，不能猜新旧 |
| 远端元数据、内容或必需资源缺损 | 不激活；保留可用旧版并报告更新失败 |

未被 Git 跟踪的技能并不等于未定制，Git clean 也不自动证明它等于源。优先用上一安装回执记录的完整文件清单和摘要核对；也可与来源明确的历史 commit 原样内容比较。没有可信基线时标 `unknown local changes`，先展示可核验差异并询问，不按版本大小或时间戳覆盖。

摘要覆盖整个技能目录：所有相对路径、文件字节、需保留的可执行位、文件/目录新增与删除，而非只比较 `SKILL.md`。mtime 不用于版本或改动判定。若排除运行时缓存，排除项必须在可信安装清单中已有明确约定，不能临时把不认识的文件都排除。symlink、跳出安装根的路径、特殊文件、嵌套仓库或无法确定的模式须单独审查，不能跟随到范围外。可执行位无法可靠读取的环境不得假定相同。

## 旧日期版本到 1.0.0 的显式迁移

[随附映射](../scripts/legacy-version-map.json) 明确列出旧源仓库、完整 commit `a890a0b69e7f518922591cc42e39d91f9b2a99ec`、每个技能旧 `metadata.version`、完整目录清单和 SHA-256，以及目标 `1.0.0` 候选。清单直接由该 commit 的 Git blob 字节与执行位产生，不根据当前工作区或时间猜测。本次映射只涵盖该 commit 的八个技能；未列出的来源不作自动迁移。

1. 先核验目标固定 SHA 及所用工具/映射的来源。使用来自该次可信候选的映射，明确记录「旧源 commit + 目录摘要 → 目标固定 SHA + `1.0.0` + 候选完整目录摘要」。映射本身不是签名或发布证明，内容哈希也不能认证来源，任意下载到的同名 JSON 不自动可信。
2. 确认本地技能名称、旧日期字段和完整目录摘要都与映射一致。日期相同但其他文件不同、增删文件、执行位变化或额外空目录均不等于匹配。只能确认 `SKILL.md` 的副本，不能推定其他内容干净。
3. 目标必须确为该次可信 `1.0.0` 候选。未知旧来源、更旧/较新 ISO 日期、错误技能名、不同目标版本、篡改映射或本地定制都保留原件并报告。不得把任何 ISO 版本统一改号、按时间新旧挑选，或因版本格式变化覆盖。
4. 匹配只证明可以准备迁移，仍须执行下面的完整目录授权、备份、替换、回读与恢复协议。已完成迁移的相同目录再次检查应为无需变化；新目标若同为 `1.0.0` 但字节不同，则报告同版漂移，不重复覆盖。

## 可选只读辅助工具

[version_advisory.py](../scripts/version_advisory.py) 使用 Python 3.10+ 标准库，不联网、不运行目录中的代码、不写安装/暂存目录、不提供安装或回滚实现。分开使用以下两类检查，不能把纯数值比较当作目录或来源已经核验。

### 跨平台纯版本值比较

`versions` 只接受两个版本字符串，不读取技能目录、frontmatter、清单或映射，不把输入当文件路径。无需 POSIX 能力，适用于 Windows 等平台的 Python；当前已在 Linux 实测并模拟 Windows 平台分支，**没有完成原生 Windows 实机验证**。从各自权威 `metadata.version` 字段读取值后，在技能根目录运行，例如 Windows 已有 Python 时：

```sh
python scripts/version_advisory.py versions --local "1.9.9" --candidate "1.10.0"
```

输出始终含 `values_only: true`、未执行的目录/内容/来源/信任/授权检查、`content_drift: "not_checked"`、空安装建议和 `overwrite_authorized: false`。只返回 `candidate_value_newer`、`local_value_newer` 或 `equal_values` 数值关系；相等不证明内容相同，较大不建议安装或覆盖。有效旧 ISO 日期一律 `mapping_required`，即使双方日期完全相同也不按日期排序，且本命令不会读取或验证映射。任一非法或未知值为 `unorderable`（退出码 2），没有大小关系；其他结果退出码 0 仅表示值检查完成，不是安装授权。此命令不接收 `updated_at`，不会用时间代替版本。

### 受保护的完整目录检查

`inspect` / `compare` 另外要求 POSIX 的 no-follow 文件描述符能力，**不支持原生 Windows 目录核验**；缺少能力时退出码 2，保留原件并交人工核验，不使用普通 Windows 路径遍历替代安全检查，也不宣称已排查 junction/reparse point。不能把 `versions` 的可用性说成整个目录工具跨平台通过。

目录命令提供格式、整数比较和完整目录摘要辅助检查；来源真实性、全部相对引用可用性、运行时加载、授权、事务与恢复仍由执行 Agent 核实，不能把测试通过或 `*_candidate` 输出当成更新完成。

```sh
python3 scripts/version_advisory.py inspect /path/to/skill
python3 scripts/version_advisory.py compare --local /path/to/installed-skill --candidate /path/to/pinned-candidate
python3 scripts/version_advisory.py compare --local /path/to/installed-skill --candidate /path/to/pinned-candidate --trusted-baseline /path/to/verified-original
python3 scripts/version_advisory.py compare --local /path/to/legacy-skill --candidate /path/to/pinned-1.0.0 --use-legacy-map
```

以上路径均为占位示例，先确认范围。只有已经核验基线来源才传 `--trusted-baseline`；只有已经核验当前工具及随附映射来源才传 `--use-legacy-map`，该开关不是授权安装。两者不具备时正常输出 `unknown_local_changes` / `legacy_mapping_required` 并保留。辅助工具无缓存排除，额外缓存也算差异；使用普通 Git `100644`/`100755` 执行位模型，不能可靠保留该模型时停在人工审查。

目录命令仅解析仓库的规范 frontmatter 子集：普通顶级键、折叠/文字描述、两空格缩进的平面 `metadata`，其值须为单/双引号字符串。它不是通用 YAML 解析器，复杂 YAML、重复键、根级 version、别名/合并键、非法缩进、含 `..` 的路径、symlink/特殊文件和嵌套仓库均失败关闭为 `unknown`（退出码 2）；平台缺少安全目录描述符能力时也交人工核验，不退回可跟随链接的读取。它不是并发锁或文件系统快照，安装前仍须重新核对整个目录；不能因为工具无法解析而说技能缺失。普通建议退出码 0 只表示检查完成，须读取 `decision`，不代表可以覆盖。

完整摘要算法：将目录及文件项按相对 POSIX 路径排序；目录项含 `path/type`，文件项含 `path/type/mode/sha256`（原始字节 SHA-256）；以 UTF-8 JSON、键排序、无多余空白、非 ASCII 原样编码，再取 SHA-256。辅助工具同时返回文件清单，方便核对新增/删除和独立复算；没有忽略未知文件的捷径。

## 更新事务

1. **准备范围。** 明确将修改的实际技能根、需要的授权和已加载的技能版本。源不可用且有缺项时已失败，不执行本段。在线补齐/升级获准后，可先创建 `.agent-workspace/<work-id>/init/` 下的最小暂存区；创建前执行同样的隐私与路径检查。这只是准备区，不代表项目初始化成功。
2. **准备完整候选。** 下载固定 SHA 下对应完整技能目录及许可证；只写 `init/staging/`，保持现有安装不动。不从任意 URL 跳转运行脚本，不 `curl | sh`，不使用会顺带修改全局配置或其他技能的安装器。连接器下载与工作区写入权限不足时报告，不绕过。
3. **验证候选。** 校验名称、frontmatter、数值版本及独立更新时间、必需本地引用、文件完整性和内容差异。检查新增的执行行为、依赖和安装后动作；发现异常或未获准的权限要求则停止该更新。目录结构变化不等于自动授权执行变化。
4. **保护原件。** 核验本地是否仍与盘点时一致，确认无其他 writer/进程在使用。保存获准替换范围的完整原件至 `init/backups/`，记录相对路径和摘要并回读；已有秘密不未经授权复制到备份。备份或校验失败时不替换。新增安装明确记录「原先不存在」，不编造备份。
5. **生效。** 使用环境支持的可靠替换方式。先验证目标路径和父路径、symlink、大小写冲突与文件权限，跨文件系统不宣称 rename 原子性。不要先删除旧版再下载。跨技能的一批更新记录逐项状态，依赖版本需保持一致；中断后不得报告整批成功。
6. **回读/恢复。** 回读真实生效路径，核对完整清单与摘要，确认旧文件没有残留形成混合版。失败则按已核验备份恢复原位置并再验证。回滚前核对目标未被其他 writer 修改；若出现并发变化，停止覆盖，保留候选和备份并报告。回滚失败则该技能不可用，init 失败，不宣称已恢复。
7. **记录。** 成功才记录已安装数值版本、独立更新时间、源 commit 和完整目录摘要；旧版迁移同时保留旧源 commit/摘要到新源 commit/摘要的映射；失败记录当前真实状态。保存本次所需目录及核验范围供离线使用。下载、暂存、备份、迁移记录均保留在 `.agent-workspace/`；清理需单独符合授权和保留要求。

记录失败若影响恢复或下一次安全判断，应报告并保留核验证据，不默默补写假的成功状态。只下载了新技能、运行时尚未识别或重载时，明确区分「文件更新完成」与「当前会话已加载」；不得通过反复读同一旧上下文假装完成重载。

## 更新受阻时

保持每个技能的真实可用性状态。已安装旧版仍可用但更新需要用户决定时，报告 `needs_confirmation`，提出具体替换/保留选择，不把完整 init 报成成功。用户明确同意保留旧版继续后，可带警告完成工作区准备。纯网络不可用且所有所需本地技能可用，可直接 `ready_with_warnings`，无需为了离线本身重复确认。
