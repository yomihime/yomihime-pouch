# 验收场景

这是需要验证执行行为时可选使用的场景清单，不是已经运行的测试结果，也不是本技能交付时必须运行的联网端到端测试。若进行模拟，使用一次性 fixture 与模拟远端，不操作真实用户项目、实际安装目录或生产凭据。执行更新验证需要符合当前执行环境的授权；本技能不附自动安装器。

| 场景 | 预期结果与检查点 |
| --- | --- |
| 源请求失败，所需技能全部缺失 | 先记录源检查失败，再做库存；报告 failed；项目、暂存区与安装目录零写入 |
| 源请求失败，部分所需技能缺失/损坏 | 点名缺项并失败；不因为有 yomihime-init 就继续 |
| 源请求失败，可信清单内技能全部可用 | 警告无法核验最新版本后继续；不联网安装，不改现有技能 |
| 源请求失败，全部可用但有未知版本 | unknown 不算缺失；带版本警告继续，不虚构版本 |
| 离线且无可信应有清单 | 不把本地现有集合当成完整；停止整套 init，需提供清单或明确缩小范围 |
| 在线，远端较新，本地与可信旧基线一致 | 固定源 SHA、准备完整目录、校验、备份、替换、回读后才报告更新成功 |
| 在线，本地缺失一个技能 | 补齐前仍不就绪；获准的新安装回读成功后才算可用 |
| 在线，同版同内容或本地版本较新 | 不重复写入/不降级；较新本地版本在报告保留 |
| 在线，同版不同内容 | 报告漂移，不覆盖；不是无需处理的同版通过 |
| 本地版本缺失、非三段数值、前导零、超 9 位、预发布或构建后缀 | 版本 unknown、文件存在；不按 mtime/updated_at 排序，不自动覆盖 |
| Windows 等平台使用 versions 纯值比较 1.9.9 → 1.10.0 | 仅返回 candidate_value_newer，values_only 为真；明确未核验目录/内容/来源/信任/授权，不建议安装或覆盖 |
| versions 比较相同数值、相同旧 ISO 日期或非法值 | 分别为 equal_values（不证明内容相同）、mapping_required（不按日期比较）、unorderable；不读取目录或映射 |
| 原生 Windows 请求 inspect / compare 目录检查 | fail-closed，退出码 2 并要求人工核验；不把纯值命令可用当作 junction/完整目录验证通过 |
| 数值版本 1.9.9 → 1.10.0，updated_at 反向排序 | 按整数三元组识别候选升级，仍核验完整本地基线；时间不影响顺序 |
| 同为 1.0.0，仅 updated_at 或非 SKILL.md 文件变化 | 同版漂移，保留本地，不当作升级 |
| 旧 ISO 版本且完整目录匹配可信 a890a0b 映射 | 只产生迁移候选，记录旧源/摘要到目标固定 SHA/摘要，授权及事务完成后才报告更新 |
| 旧 ISO 相同但有新增文件、删文件、执行位变化或其他目录修改 | 保留全部本地内容，不因改成 1.0.0 而覆盖 |
| 旧 ISO 日期较新/较旧、无映射或目标不是映射的 1.0.0 | 不跨格式比较，不自动迁移，报告需要可信映射或明确决定 |
| 只读辅助工具遇复杂 YAML、重复键、symlink 或嵌套仓库 | 输出 unknown，不跟随、不改文件、不伪装成功 |
| 候选 updated_at 缺失、非 UTC 或非法日期 | 报告候选元数据损坏，不激活；不得据此改变版本大小 |
| 本地较旧但已定制、含新增文件或没有可信基线 | 保留原件，报告差异与需确认动作；不会用新版抹掉定制 |
| 下载时 main 移动 | 所有候选文件仍取最初 SHA，不混合新旧版本 |
| 候选缺资源、下载中断、备份失败 | 不替换可用本地版本；报告未更新和具体失败点 |
| 替换后校验失败 | 验证恢复旧版；若恢复失败则标不可用并失败，不能报告恢复成功 |
| 盘点后发生并发本地写入 | 停止覆盖/回滚，保留双方内容与证据，请求协调 |
| 同名技能有多份 | 找实际生效路径；优先级无法核实则需要确认，不随意更新第一份 |
| 本技能有新版但会话仍加载旧版 | 先暂存、最后更新；记录文件版本及当前加载版本不同，不混合执行 |
| 新项目无工作区 | 仅按需生成 `.agent-workspace/` 下必要文件，代码、依赖、共享忽略和暂存区不变 |
| 旧目录的记忆/指南/任务材料用途明确且无冲突 | 映射、校验、获准迁移、修复引用并验证；历史与证据可恢复，无旧路径 fallback |
| 旧目录混有代码、真实数据、symlink 或活动任务 | 只处理可证实且获准项，其余保留并列阻塞；不整体重命名/删除 |
| 目标已有不同指南或多个 current.md | 不覆盖、不按 mtime 任取；保留候选和来源，取得决定后再合并 |
| 没有架构源但本次需要标准架构图纸 | 按需使用 architecture/ 稳定目录，不以 architecture 作 work-id；同范围一份跨任务 JSON，不强制全仓建图 |
| 旧任务或 memory/references 中已有有效架构源 | 原位复用并记录真实路径/修订；不复制到默认目录、不把它当普通临时材料清理 |
| architecture.md 仍为正式权威或多个图纸源冲突 | 保留原文，核对入口与来源，先协调权威和获准转换范围；不自动降级、覆盖或凭 mtime 选择新源 |
| 已确认 JSON 权威且存在架构现状说明 | JSON 按对象保留现状/目标/验证状态；architecture.md 只保留经证据确认的现状与源引用，不复制契约表 |
| 获准迁移架构源但旧任务/网页仍引用原路径 | 核验内容、恢复依据和实际引用；未闭合前保留源并报告，不能只改当前入口就宣称完成 |
| 项目代码引用旧目录 | init 不改代码；保留受影响来源并报告需要另一个代码任务 |
| 根 AGENTS.md 有无关人工指导 | 原位保留；只改获准的相关入口，其他字节/语义不受影响 |
| 私有文件已 tracked/staged | 不称 exclude 已解决问题，不 untrack/清空暂存；阻止误发布并报告 |
| 成功后再次 init，没有源/内容变化 | 无重复迁移、备份、模板或权威指南；不改项目代码、不改现有成功状态 |

验收回执标明 passed、failed、skipped 或 unrun，并保留用例范围、输入版本和具体证据。静态检查只能验证技能文档与引用结构，不证明真实 GitHub 连通、安装或旧项目迁移成功。

只读辅助工具的 fixture 回归可用 `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s skills/yomihime-init/tests` 运行。测试子进程使用解析后的 Python/Git 绝对路径、最小环境和隔离用户目录，以及 15 秒默认超时；不继承凭据、代理或启动钩子，Git 禁用网络协议。它们不安装到真实用户目录，不执行网络或发布，不能替代上表中授权、事务及宿主加载的真实验证。

平台证据分开报告：纯值逻辑及 CLI 在 Linux 执行，Windows 分支以模拟验证且禁止文件读取；原生 Windows 实机验证未执行。完整目录核验仍仅支持具备安全描述符能力的 POSIX 环境。
