# 需求切片、层次与执行轮次

## 从需求到角色任务

采用稳定标识关联，不要求为每一层单独创建文档：

| 层级 | 描述 | 验收归属 |
| --- | --- | --- |
| REQ | 有来源的用户目标与约束，区分已有行为、建议和假设 | 可观察的用户/系统结果与非目标 |
| 里程碑 M | 一组能体现实际价值的能力闭环 | 集成后的里程碑场景、风险和退出条件 |
| 切片 SL | 可独立实现、验证或提供明确基础契约的工作单元 | 自身断言，以及归属的集成验收 |
| 角色任务 JOB | 实现、架构、设计、测试、审查等具体委派 | 对应产物与角色必需材料；子任务完成不代表切片/里程碑完成 |

同一需求可以跨多个切片，多个需求也可共享基础切片。设计纵向可运行闭环：入口、核心行为、输出和验证贯通；避免只列“后端完成/前端完成”却没有集成接受者。数据库迁移、接口或构建基础确需单独切片时，明确消费者、兼容约定和后续整体验收，不能将基础完成当作用户功能完成。

每个切片按需记录：

```text
id / REQ 与里程碑 / 目标、非目标、可观察产物
输入来源与契约版本 / 上下游依赖 / 是否已接收
相关代码地图、现状/目标图纸及其确认状态
源码写入范围与共享契约 owner / 环境和资源
风险、不变量与恢复条件 / 本切片检查与集成验收
角色任务与交付者 / layer / 所属 round/wave / 检查点 / 候选
完成证据、缺口、受影响任务和下一步
```

架构切片只在存在需要先解决的边界、契约或高影响假设时建立；输入包含目标、约束、关键质量属性和受影响代码证据，产物可直接放入主计划或引用已有权威架构产物及其基准/状态/范围。视图按具体决策选取，不能为凑齐视图制造依赖；其退出条件是下游所需契约与证据就绪，不是“图已画完”。采用 `architecture-design` 时按需加载；缺失不阻断无关切片，也不要求安装。跨任务图纸引用已有唯一源，无源时才按需放入 `.agent-workspace/architecture/`；切片完成须交接稳定入口、源修订/状态和后续 writer，不能只留易被清理的任务产物链接。保留仍在使用的源及引用，不擅自迁移、覆盖或在 project-memory 再建副本。

范围足够小到执行者能明确开工和判断完成，足够完整到能验证行为。不要按固定文件数、函数数、小时数或 Agent 数切片。没有地图时允许有界调查，不因文档未齐让所有实现停摆。

## 依赖层次

区分真实工程架构层与本任务的依赖层次。layer 按前置关系确定深度，round 按这些关系安排执行顺序；真实架构层不强制全层完成，但已定义的执行轮次必须遵循其屏障。

依赖应说明具体类型：

- 契约依赖：接口、状态、数据格式或权限语义需先确认，版本要兼容。
- 产物依赖：调用者需要实际代码、包、数据迁移或已接收结果。
- 验收依赖：局部可以实现，但某个集成结论需要其他切片和真实环境。
- 资源或写入冲突：共享文件、页面、数据库、端口、构建目录需串行占用；它是调度约束，不伪装成业务依赖。

发现循环时先定位互相依赖的实际内容，抽取稳定契约、缩小切片或安排一次接口决策，再释放下游；不能用多开 worktree 消除语义循环。共享契约由单一 owner 维护，其他任务只引用有效版本。

## 顺序轮次、轮内并行与检查点

round/wave 是有顺序的执行轮次，内含 1-n 个可并行任务，轮末按计划执行测试/审查检查点。不是固定修复轮数、时间片或每轮用户审批。每个任务的准入条件分别判断：

1. 本任务目标、验收、约束与权限明确；所属轮次已开放，必需输入和直接依赖已经接收。
2. 任务包的契约、候选和相关地图基准兼容；存在具体缺口时先补足受影响部分。
3. 写入/资源可用且与其他活动任务无冲突，实际运行容量与用户硬限制允许。
4. 能交付独立结果，委派的收益足以覆盖沟通与上下文重建；短任务可由主调度者直接做。

同轮任务按实际容量和资源安排，容量不足时分批启动，不改变它们的轮次归属。本轮全部任务通过或非必需项有理由地显式跳过后，按顺序执行检查点；所有必需检查点通过才开放下一轮。不能靠只标里程碑完成、跳过必需项或提前上报未来节点来越过屏障。

例：R1 确认接口 A 并通过方案审查；R2 并行实现 B/C 并通过集成测试；R3 执行依赖 B 的 D 与交付检查。即使 B 先完成，D 也等待 R2 的 C 和检查点通过。规划者应据需求与风险选择轮次粒度，不能执行时擅自将有屏障的轮次当自由 DAG 调度。

每个检查点说明类型、证据与候选、通过条件、失败时可返回的当前/更早轮次。失败记录原始结果后停止启动新工作，继续接收已在途节点的真实终态；这些回报不解除失败、顾问或阻塞状态。由主调度者选择直接返回、请顾问后返回或保留阻塞，返回前收齐已完成结果。判断与特殊情况用事件备注记录，不能无声重试或伪造通过。返回增加尝试编号并保留旧结果，未完成任务先协调停写/交接并记明事实；工具重置不等于源码或进程被回滚。

同一切片实现、自检与返修优先原实现者；架构/设计任务在当前契约交付后可退场。审查和顾问按候选/具体问题就绪后启动，保留上下文的成本和线程容量按工具核对。

## 计划、任务包和变化

在已有计划或 plan.md 维护需求与验收；执行定义通过观察器计划事件保存，当前投影由事件重建，不再人工重复维护两份任务状态。current.md 保存恢复必需的目标、有效轮次/尝试、里程碑、候选、结果与下一步，不要求读全部历史轮次才能恢复。

派工只提供本 JOB 的 REQ 摘要、里程碑/SL、layer/wave、具体前置与验收、相关地图/图纸、候选、写入资源和角色必需材料。其余给可访问路径按需读；不复制完整切片树和全部阶段日志。

需求或接口变化时标记受影响切片、任务、地图和证据，更新有效输入版本并通知相关角色；未受影响工作继续。旧消息不回退新决定。不能靠给失败任务换编号重置用户硬限制或掩盖未闭合问题。
