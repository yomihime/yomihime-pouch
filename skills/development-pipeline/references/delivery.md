# 交付终点、变化回流与收束

## 按本轮终点交付

任务接入时确定本轮范围。调查终点是有证据的发现与建议，方案终点是可执行计划，本地修改终点是相应实现/验证结果；准备包、PR、安装和发布各需要明确范围、操作授权与对应证据。达到一个终点不自动授权下一个。

候选来源、实际内容和用户目标明确后才接受交付。优先复用有效候选和验收；若要求的已安装/已有包与目标完全匹配，核验其身份与内容后复用，不重复构建。来源或范围不足时报告缺口，不拿相似版本充当目标。

Git、构建与真实环境各遵循项目已有流程，保留 dirty/staged 文件及私有材料。PR 沿用现有分支/PR 约定；不为看起来干净而 reset、stash、clean 或覆盖改动。发布/部署/回滚不是普通流水线的默认副作用。

实际任务需要 tag 发布等专项操作时，按可用的对应专项技能和授权执行，提供已核验候选、版本范围和发布资料；若条件不具备，明确停在哪个已完成终点和仍缺什么，不假称调用了工具或专项流程。

## 候选变化与失败回流

- 代码缺陷：回原切片/实现者，保留失败复现；修复后产生新候选并复验受影响断言。
- 接口或架构冲突：owner 与主调度者裁决契约，更新图纸、依赖和受影响任务输入版本，再继续相关写入。
- 环境或工具失败：核对配置、权限、网络、资源与实际环境；不把它伪装成代码通过或盲目升级模型。
- 新需求、授权撤销或约束收紧：核对在途操作与既有副作用，更新目标、验收、切片和任务版本；未受影响授权工作继续。
- 无实质进展或高影响假设失效：围绕具体问题请顾问或调整切片；不设默认固定修复轮数、续批次数或时间窗。

按需求/接口/候选的影响追踪证据失效，不默认回到全项目第一阶段，也不把旧测试自动归给新代码。阶段退回和模型/人员调整都不能重置用户明确的硬限制。

使用观察器时，失败进入 needs_decision 并停止启动新工作。此前已运行的任务在 needs_decision/consulting/blocked 仍需提交真实终态、候选和证据，接收结果不改变未解决失败或当前决策状态。返回前先接收已完成结果；实际取消/交接的未完成工作记录事实，并在确已停止/交接后才声明 --quiesced。主调度者选择具体返回轮次或阻塞；return 增加 attempt，重置该轮及下游节点，旧失败和旧通过仍留历史。它只重排工作，不自动回滚代码、数据或终止进程。新尝试重新上报候选与证据，复用旧证据需核验适用性并明确原因。

## 交付回执与项目记忆

最终回报说明本轮目标、实际完成终点、对应里程碑/REQ、候选与产物位置、验证/审查证据、未验与阻塞及后续动作。代码存在、脚本生成、命令退出、CI 标记、运行启用和真实业务成功不混成一个“已完成”。

有包时给实际来源、内容身份和必要包检；有外部操作时给可核验对象、动作和结果。异步发布或 CI 仍在运行时说明状态，未完成结果不能提前宣布通过。没有操作就不生成伪回执。

用 project-memory 将仍有效的阶段/里程碑、候选、决定、代码入口、调试知识、结果、缺口和下一步归并成完整 current.md。细节继续位于计划、实例报告与地图，避免第二份状态总表。归档、证据固化和并发保护沿用其协议。

收束时核对：正式交付内容与允许清单、长期证据和引用、临时脚本是否升级为正式工具、后台进程/页面/端口等资源负责人、未提交改动及接替检查点。主仓库主 checkout 的并行 writer 保持文件范围互不重叠；完成的 Agent 先交接并接收结果、证据和写入权，再按运行时能力回收，确认 Agent 和后台进程不再占用后才将实例材料列为清理候选。multi-agent-engineering 可提供细则；没有该技能时由主调度者执行上述核验，不声称无法确认的回收已完成。Cleaner 仅处理范围已授权且引用/占用/恢复核验满足的准确批次；记忆 archive/ 与真实数据不当普通临时文件清理。

清理保留项目 `.agent-workspace/` 索引、流水线 `events.jsonl`、需留存的历史与 `report.html`，保证已归档运行仍可从索引发现并访问；归档分类本身不移动或删除运行。若引用、恢复或占用无法核实，保留相关材料并报告。

默认静态观察器无常驻服务；completed 自动停止网页轮询并保留 report.html，报告完成不扩大任何发布或删除权限。可选 HTTP 兼容服务由启动者停止；未完成/阻塞不改成 completed 来强行收尾，观察页关闭也不等于任务进程已结束。

未获后续发布或清理授权不妨碍接收已完成的本轮结果。保留实际待验与待授权边界，后续从现状接续，不重复重放全部流水线历史。
