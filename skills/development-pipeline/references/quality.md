# 分层验收与质量控制

## 验收从需求和风险开始

实现前定义关键成功条件、不变量和反例，测试依可观察行为设计，不逐行复述当前实现。根据影响选择检查范围和独立性；轻微文档/低影响修改可采用局部核验，涉及权限、数据、并发、迁移、资源生命周期或关键交付的变化采用相应真实环境与独立审查。

同一需求需能追到切片、实际候选、方法/环境、断言、原始结果和审查处置。覆盖率和扫描工具只是信号，不能替代需求断言，也不设置所有工程统一的百分比目标。

## 质量层次与检查点

| 层次 | 核对内容 | 退出所需依据 |
| --- | --- | --- |
| 需求与契约 | 验收可观察，输入输出、权限、错误语义和不变量明确 | 需求来源、有效契约与关键待决项；高影响歧义已处理 |
| 切片自检 | 行为、边界、失败分支及必要静态/单元检查 | 实际断言与结果，范围内代码和用例可复现 |
| 模块/服务集成 | 调用、数据/事件传递、依赖版本、接口兼容、集成资源 | 集成候选上的契约与场景证据，不能仅用各模块单测拼出通过 |
| 产品/目标环境 | 用户主路径、真实运行时、界面状态、设备/外部服务 | 约定环境与实际操作结果；缺条件明确待验 |
| 独立审查 | 需求覆盖、正确性、安全和遗漏，证据是否足够 | 未参与候选方案与实现者的独立意见；位置、影响和依据 |
| 交付与恢复 | 源码、构建、包与目标身份一致，配置/数据保护与必要恢复 | 本轮终点对应的产物核验、操作证据和剩余风险 |

这些层次按适用性形成检查集合，不强制每个小任务执行所有测试，也不能用较低层证据替代要求的较高层验收。测试设计可以提前进行；执行需稳定候选，最终接受需覆盖实际集成结果。

将必要检查安排为轮次末有序检查点，至少最后一轮含必需 test 或 review。检查点需等待本轮任务和前置检查点满足，必需项不得跳过。观察器对 passed 强制候选与现存证据文件并记录哈希，这只证明报告关联的文件身份；测试断言是否真实成立、候选是否与实际代码一致和独立审查是否充分仍由执行者与接收者核验。

## 按风险选取的质量维度

- 正常与边界：有效、空、缺失、超界和格式异常输入，结果与错误符合契约。
- 状态与失败：重复调用、取消、重试、部分成功、超时、异常恢复及资源释放按实际语义验证。
- 并发与一致性：竞争、重复写入、幂等、状态所有权与事件顺序；只在实际有关时设计相应证据。
- 安全与隐私：权限与身份边界、未授权路径、秘密与私有材料处理，不因 UI 隐藏或 mock 通过认定安全。
- 数据与兼容：旧配置/数据、依赖、序列化和公共接口；迁移需按范围验证数据保留和恢复路径。
- UI 与可访问性：真实渲染、主路径、空/加载/错误/重试、键盘与布局边界；截图不证明数据已保存或真实服务成功。
- 性能与运行：需求有时延、内存、容量或启动/退出约束时，先定义环境与可观察指标，再验证；不凭模型估计宣布满足。
- 可维护性：职责、依赖、必要文档/地图与正式工具能随实际交付工作，不遗留影响行为的临时路径。

不把以上清单变成所有工程必开的角色或无差别全套测试。裁剪须说明适用性，必需项仍未验就保留缺口。

## 验收矩阵与证据

可在现有计划/报告维护下列字段，不要求另造文件：

```text
REQ / 不变量 / 里程碑与切片
检查方法、命令或操作 / 环境、数据与候选身份
预期行为或断言 / 是否必需及适用性
passed / failed / skipped / unrun / 原始证据位置
审查发现与严重级别 / 影响、处置与复验候选
当前验收结论、剩余缺口和下一步
```

记录实际命令退出、用例/断言结果和关键错误，不能只抄最后一个成功摘要。未执行写 unrun；主动跳过写 skipped 并给原因；不满足断言写 failed。构建成功、测试成功、审查接受、CI、包检、安装和端到端分别陈述。

候选可以是 commit、含 staged/unstaged/untracked 的内容清单、不可变包及其校验，或其他可核验身份。只记 HEAD 会漏掉实际被测 dirty 文件。记录与本检查相关的依赖、配置、环境和数据基准；保留日期不代表重新运行。

冻结必须作用于实际代码/包与环境：使用稳定 checkout、隔离副本或候选包，协调资源占用。不能边改被测文件边把结果记为同一稳定候选；必要时重新标识候选和重验受影响项。

## 独立性、发现与阶段退出

自检不能冒充独立审查。审查者收到原始需求、正式契约、实际候选及差异和原始证据，先独立判断，再对照作者说明；图纸、作者摘要和旧通过不是全部材料。参与方案或返修的顾问/架构师不代替该候选最终独立审查。

Blocker 表示不可交付问题，Important 表示实质正确性/验收风险，Polish 为可选改进；每项含具体位置、影响、候选与证据。协调者按需求和事实处置分歧，记录接受、拒绝依据或用户明确的范围变更，不能为过关降级问题。

某个验收范围只有在所需输入与产物匹配、必需检查满足、要求的独立审查完成、Blocker/Important 闭合后才可接受。缺独立工具或目标环境时保留未满足项；不得把 skipped/unrun 记成满足门槛。用户明确改变验收或目标时保留来源、影响和未验事实，不追溯改成原要求通过。

局部检查通过只释放满足其契约的下游，不代表整里程碑或产品安全。Skill 提供证据化质量控制，真实可靠性仍取决于实际实现、环境与验证覆盖；不承诺零缺陷。

## 失败与证据复用

失败保留原始候选与结果，交回相应实现/契约/环境责任者。复验针对新候选和受影响依赖/场景；没有根因进展时改变假设或请顾问，不机械重复。

复用旧结果要核对来源候选、改动范围、接口/依赖/配置、环境与数据是否仍适用，并记录依据；受影响或无法确认的检查重新运行或标待验。最终包若与被验源码/依赖不同，先核对来源和差异，不能沿用原身份。无关改动不要求整套重跑，缺证据也不能声明复用成功。
