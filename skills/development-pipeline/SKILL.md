# 开发流水线

用户调用技能的主对话负责推进到本轮约定终点。用明确的需求、依赖、产物和证据组织工程；角色调度可交给 multi-agent-engineering，知识与恢复可交给 project-memory。它们可选，缺少工具时可顺序执行，不能冒充独立审查或真实运行。

## 接入与范围

- 先遵循有效指导、最新用户要求与已有计划，核对实际工作区、当前改动和必要资源。采用 project-memory 时主调度者完整恢复 current.md，其他角色按任务取相关知识。
- 本地计划和运行材料统一使用 `.agent-workspace/`。首次开工或旧项目材料尚未整理时由 yomihime-init 盘点并安全组织，日常流水线不搜索旧目录或双写；缺少该技能时保留现有材料，报告待整理项并继续不依赖迁移的工作。
- 明确需求来源、非目标、风险、验收与本轮终点：调查、方案、本地候选、包、PR、安装或发布分别对待。普通技术决策自主处理，必要权限、关键产品取舍或用户保留决定才请求确认。
- 保留用户源码、暂存/未提交改动、真实配置与数据、私有记忆和恢复材料。任务、角色、历史和流水线阶段都不扩大权限，不默认提交、推送、安装、发布或清理。
- 根据任务选择轻量修复、常规开发、架构/数据变更或已有候选交付路径。复用已有有效契约与证据，不强制全仓测绘、完整设计或所有阶段文档。

## 切片、层次和轮次

按 [需求切片与调度](references/slicing.md) 将有来源需求关联到里程碑、可验收切片和角色任务。切片说明可观察产物、输入契约、依赖、写入/资源与验收；优先可运行的纵向闭环，必要的基础切片明确其集成验收归属。

层次表示实际依赖深度；轮次是按计划顺序执行的边界，每轮安排 1-n 个可并行任务及必要的有序检查点。本轮任务完成、必需检查点通过后才开放下一轮，不能仅因某个前置任务结束就越过轮次。循环依赖先明确契约或重新切片，同轮写入/资源冲突串行处理；轮数不等于固定返修次数。

## 按需架构工作

新系统、重大模块/接口/状态所有权变化，或迁移、并发、部署/信任边界影响验收时，安排相应架构任务；运行时有 `architecture-design` 则按需加载，无则基于需求与受影响代码做有界分析，明确缺口，不自动安装。复用已有主计划与权威架构产物，按问题选择边界、依赖、契约和关键流程等视图；部署、数据、失败恢复等内容仅在相关时展开，各视图与同一来源一致。普通小修改只核对直接受影响契约，不为图纸完整而增设阶段、文件或角色。

跨任务架构图纸原位复用已有唯一源；只有无源且确有需要时，按需使用 `.agent-workspace/architecture/`，不将长期源归入单次 pipeline/jobs/scratch 的可清理产物。已有 `AGENTS.md` 或 `memory/current.md` 入口登记同一源及修订、现状/目标状态和维护 owner，current.md 仍直接保留恢复所需概览，不另造 project-memory 图源。交付与角色退场前核对入口可读、源与引用修订一致、writer/接收者及仍需保留的依据和视图；完成轮次或清理运行目录不删除这些长期材料，不擅自迁移或覆盖已有源。

架构工作进入实现的条件是本切片边界、不变量、输入契约和验收方法足够明确，高影响待决项已处理；关键可行性假设按风险用原型、契约检查或真实环境验证，证据不足仍标待验。图纸存在、方案已接受或架构任务结束不等于运行验证通过。把必要验证关联到现有切片和检查点，候选变化后复核受影响契约与证据，不另建执行状态或事件协议。

## 阶段与退出条件

| 阶段 | 需要的结果 | 退出条件 |
| --- | --- | --- |
| 基线与验收 | 需求、非目标、终点、候选与风险、可观察验收 | 当前切片的关键要求和权限足够明确 |
| 方案与拆片 | 必要图纸/契约、切片与任务依赖、顺序轮次及检查点、资源分配 | 本切片输入就绪且所属轮次已开放 |
| 实现与自检 | 代码、必要测试与地图变化、自检结果 | 产物在范围内且可核验，失败交回对应切片 |
| 集成候选 | 来源明确、内容稳定的实际修订或包 | 代码、dirty 文件、依赖、构建身份与被验候选能对应 |
| 验证与审查 | 分层验收矩阵、原始证据、必要独立审查与发现处置 | 必需验收满足，Blocker/Important 闭合，结果绑定候选 |
| 获准交付与收束 | 本轮终点对应结果、完整记忆、证据与产物去向 | 实际交付达到约定，未知/未验与待授权事项如实保留 |

同轮独立任务的实现与自检可交叠；检查点等待本轮任务达到条件，跨轮严格按通过结果推进，最终验收针对集成候选。阶段过程状态与 passed/failed/skipped/unrun 分开，不能用“阶段已结束”覆盖失败。

源码工作使用主仓库主 checkout；并行写入按互不重叠的文件范围分配，共享文件指定唯一 writer。完成的 Agent 先交接并接收结果、证据和写入权，再按运行时能力回收，材料仅在确认不再占用且获得清理授权后处理。可用时按 multi-agent-engineering 细化协作；不可用时仍按这些写入、交接和回收规则执行，不假定另一个技能已安装。

失败进入 needs_decision，禁止开始新工作或推进轮次；此前已 running 的任务仍可提交 passed/failed，保留该 attempt 的候选和证据。在 needs_decision、consulting 或 blocked 期间接收这些终态，不改变未解决失败或已有决策状态。主调度者先收齐已完成结果，再选择顾问、返回或阻塞；实际取消/交接的未完成任务以备注记明事实。返回保留历史，创建新 attempt，并重置目标轮次及下游结果；它不是 Git reset、数据回滚或自动终止进程。顾问按具体问题调用，遵守已有模型与预算边界。

## 质量控制

按 [分层验收与质量](references/quality.md) 在实现前定义关键行为与不变量，按风险选择检查和独立性。安全、数据、并发、恢复与真实环境等高影响要求必须有相应证据；覆盖率、静态检查、CI 标记或截图不能替代具体断言。

审查项含位置、影响、候选与证据，分 Blocker / Important / Polish。未闭合 Blocker/Important 不交付该候选；必要检查 failed、skipped、unrun 或环境不可用时保留缺口，不改名为通过。用户明确调整范围或验收时记录来源与后果，不自行降标准。

失败回原责任范围：实现缺陷回原实现者，契约冲突回 owner 与主调度者，环境问题处理环境，关键假设失败或无进展请顾问。只重验受影响证据，复用必须说明适用性；不默认从头重跑、固定修复轮数或逐次续批。

## 任务与记忆衔接

- 主调度者将阶段/里程碑、layer、slice、round/wave、检查点、验收与候选关联到任务。使用 multi-agent-engineering 时生成 task-handoff-v1，并附本任务相关的这些字段及流水线运行目录/节点 ID；不把全部流水线历史交给子 Agent。
- 用 project-memory 的 knowledge-extract-v1 提取相关事实、地图与图纸，连同需求、验收、权限和基线形成可开工输入。测试、审查、维护、cleaner 等角色仍需其必需环境或原始材料，地图不能补足这些缺口。
- 各角色按原任务回报协议返回实际产物、候选、证据与缺口。普通事实可直接澄清，公共契约/范围/验收变化由主调度者协调版本并通知受影响任务。
- 复用已有主计划或 .agent-workspace/<work-id>/plan.md 管详细需求与验收；current.md 直接记录目标、当前轮次/attempt/候选、关键结果、阻塞和下一步。各运行的 events.jsonl 是机器事件源，项目索引、网页/API/status 由此派生，不再人工维护另一份进度表。

## 每步汇报与观察页面

采用 [观察器契约](references/observer-contract.md) 和 [操作说明](references/observer.md)，以项目 `.agent-workspace/index.html` 作为固定入口，查看活动和历史运行并进入各自详情。每项目/运行独立目录与身份，预制静态网页由标准库脚本更新相邻数据文件，默认无需服务或端口。规划时逐步提交定义，执行时上报语义事件。主调度者在结构更新、任务开始/结果、检查点、顾问、返回或阻塞时向对话转发简短摘要；无需为每次读文件或 shell 调用输出完整图。

运行详情页刷新轮次、并行节点、检查点、失败返回边、当前尝试、备注和时间线；completed 后停止刷新并自动生成单文件 report.html 供最终查看。view 可从事件重建组件与投影，投影失败而事件已落盘时不重复上报。有新结构可用 status --mermaid 在对话展示图。索引和详情只读，数据来自执行者上报，不能独立证明进程仍在运行或代码通过，也不能向聊天自行发消息；工具不自动执行 Agent、产品命令或发布。

交付、证据复用和收束按 [交付与变化处理](references/delivery.md)。首次实施读取切片参考，制定验收读取质量参考，交付/候选变化时读取交付参考；不要求每个子 Agent 加载全套技能。

质量能力表现为可追溯需求、可复现验证、候选一致、独立判断和风险显式处理。Skill 指令不证明工具实际执行，不承诺零缺陷或未验证平台可靠。
