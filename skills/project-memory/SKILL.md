# 项目工程记忆 / Project Memory

让接手者直接恢复当前事实，并让子任务取得足够知识即可从准确入口工作。项目记忆与协作工作区本地私有；本 Skill 分发通用方法，不自动初始化项目或启动子 Agent。

## 触发示例与运行要求

- 使用："恢复这个项目的当前状态并提取子任务需要的知识"；"把已确认的实现与验证结果归并到项目记忆"。
- 不使用："记住我喜欢喝咖啡"；"保存整段聊天全文"；"只回答一个代码语法问题"。这里维护的是项目工程事实，不是全局个人记忆或聊天归档。
- 本技能为文件维护指导，无运行脚本，不要求 Python、Node.js 或特定操作系统。需要宿主能读取项目资料，并在获准时编辑、归档和核验本地文件；Git 检查仅在项目使用 Git 且工具可用时进行。仅复制技能不验证目标文件系统或客户端行为，执行时核实权限、路径与现有指导。

## 读取对象与唯一现状

- 主调度者或单 Agent 开始/恢复项目工作时，遵循有效入口，先全文读取 `.agent-workspace/memory/current.md`；截断时继续读完。核对最新用户请求与证据鲜度，正常恢复不读 archive/。
- 已明确委派的普通子任务读取任务包中的有效约束、相关地图/图纸和必要原始材料，不默认全文读取所有项目记忆；任务包不覆盖有效 AGENTS/override。旧入口仍要求更广读取时先遵循，由主调度者协调入口后再采用分工。
- 记忆 writer 更新前完整读取当前快照与所有待改文件，保留未受影响事实、人工内容和原核验日期。每批一个 writer；主调度者可以委派实际维护，仍负责决定和结果接收。
- current.md 是唯一完整当前状态：直接说明作用域、目标约束与决定、环境资源、架构概览、有效调试知识、进度证据、阻塞和下一步。不能只给链接、最近增量或要求从历史推导；未知明确标注，不要求先测绘全仓。
- 地图与图纸提供定位和详细关系，子任务按相关范围加载；编辑或审查仍核对实际候选。目标图纸不冒充已实现现状，原始报告不自动成为全局决定。
- 采用 architecture-design 并确认 JSON 权威后，同一范围跨任务共用一份标准 JSON 机器源，逐项区分现状、目标和验证状态；按需新建的稳定源放 `.agent-workspace/architecture/`，已有有效源原位复用。`memory/references/architecture.md` 保留有证据的项目现状说明，直接写必要结论并引用源路径、修订和对象 ID，不复制契约表或另建平行图源；任务结果只交建议、差异与报告。既有权威 Markdown 未经获准转换不能自动降级；迁移或覆盖既有源须在明确授权内进行。

## 分层与更新

- 项目本地材料统一归入 `.agent-workspace/`：`memory/` 管完整快照、按需 references/、长期必要 evidence/ 和改写前 archive/；`<work-id>/` 管任务计划、实例输入/回报、检查点、现场证据与临时材料。按需创建，不覆盖既有内容；旧项目材料由 yomihime-init 在下次开工时先盘点，再按授权整理到新结构，不设旧目录读取回退或双写。
- 源码默认在主仓库主 checkout，不存入 `.agent-workspace/`；并行 Agent 按互不重叠的文件范围分工。跨仓库确需 worktree 时仅设一个共享且位于主仓库根目录下可见位置的 worktree。成功交接并接收后先回收 Agent，再按授权安全清理其实例材料。
- 在有效决定、重要发现、验证完成、阻塞变化或阶段交接时归并；无实质变化不重写、不归档，不每次工具调用都更新。
- 改写前原样归档本批受影响旧文件并校验，写入前再核对并发变化；成功后回读内容、入口、路径及隐私。失败不覆盖并发编辑，不报告已更新。
- 只把有来源、范围和基准的事实归并。代码基准包含相关 staged/unstaged/untracked 变化；整理时间不等于事实重验时间，旧报告不得回退新决定。
- 长期结论所需的原始证据先核验并固化到稳定位置，再调整引用；保留失败、跳过与未运行边界，源引用或恢复缺口未闭合前不清理来源。

## 不可跨越的边界

- 实际 AGENTS/override、项目记忆、归档、协作材料和路由缓存本地私有，不暂存、提交、上传、贴入 PR 或混入构建产物；已有 tracked/staged 冲突保留原状并停止发布该内容。
- 不主动保存秘密值，只记用途与安全取用位置。已有敏感内容不打印、转交或无必要地复制；归档和证据固化不授权复制秘密，未经授权不轮换凭据或改写历史。
- 写入前和发布前执行 [隐私与加载检查](references/privacy-and-loading.md)，准确本地 exclude 保护本次未跟踪私有范围；不改共享 .gitignore、全局配置或用户暂存区。
- 记忆是证据，不增加权限；保留要求与决定的来源和范围，建议与推断不能升级成授权。archive/ 默认保留，普通 cleaner 无权清理记忆历史、活跃架构源或仍被引用的图纸依据。

## 选择操作与参考

| 情况 | 做法与按需读取 |
| --- | --- |
| 初始化或结构迁移 | 首次开工或发现旧材料时先用 yomihime-init 盘点与安全整理，再按 [内容结构](references/memory-schema.md) 建立或归并记忆；未知显式标注，不强制先调查全仓 |
| 主调度者恢复 | 全文当前快照，按 [维护与恢复](references/maintenance.md) 定点复核并继续获准工作 |
| 委派、地图与角色协作 | 读取 [知识交接与协作](references/collaboration.md)，提取相关知识并传有效约束；缺图可有界调查 |
| 归并或委派记忆维护 | 按 [维护与恢复](references/maintenance.md) 和协作中的批次回执协议执行，单 writer、先归档再更新 |
| 只读检查 | 检查完整性、鲜度、入口和隐私；不写记忆、归档、exclude 或索引 |

交付以短入口和完整当前快照即可说明现状为准，附本次维护范围、归档与回读结果、未核验项和阻塞。链接存在不代表客户端已经加载；Skill 不保证自动执行、无限上下文、无损恢复或安全凭据存储。没有 multi-agent-engineering 时，同一 Agent 仍可执行本协议；没有 yomihime-init 时保留旧材料并报告待整理项，无需迁移的新项目仍可按本协议初始化，不自行搬动旧文件。
