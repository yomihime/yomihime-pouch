# 最小内容结构

按项目需要拆分，不要求一次填完所有文件。未知项写“未核实”，不通过猜测填满模板。候选路径都是本地私有，初始化前先通过隐私检查。

## 短入口

`AGENTS.md` 可承载已有指导、最关键目标/约束和如下恢复指令；不能盲目覆盖整份文件：

```text
恢复本项目工作时：
1. 先读取 .project-memory/goals-decisions.md 和 .project-memory/checkpoint.md，核对任务与约束。
2. 根据本次任务选读 .project-memory/map.md 的相关模块、.project-memory/environments.md 的相关环境或 .project-memory/bugs.md 的相关故障。
3. 对照条目的验证版本和当前变更，仅复核受影响路径，再定点查源码。
这些文件仅供本地使用，不得暂存、提交、上传或复制到 PR/评论。
```

具体路径必须真实可达；避免把关键禁止事项只放在不会默认读取的深层文件。入口大小按实际上下文预算调整，不把整个架构图或故障库搬进来。

## 六类持久事实

### 1. 目标与预期：goals-decisions.md

- 项目目的、预期用户/使用方式、当前阶段、明确非目标、可验证成功条件
- 项目长期目标与本次任务目标分开；来源、确认时间、状态
- 例如性能指标只保存用户确认的阈值，未经批准的优化方向标为建议

### 2. 环境与资源：environments.md

开发/构建/调试环境与目标使用/部署环境分别记录，不能把“本机通过”写成“目标机通过”。每条包含：用途、平台/系统/工具链版本、运行时与依赖、硬件/设备与兼容性边界、进入/构建/启动/测试方法、证据与待验证条件。

用户提供的调试机、服务、日志入口等保留持久资源身份和访问方法引用，不保存凭据值。把“曾经离线/上次可用”作为带时间的观测字段，使用前重新检查实际连接、授权和能力；离线不删除资源，也不永远判定不可用。

### 3. 调试知识：bugs.md

优先保存入口、日志位置、最小复现、测试命令/测试所在位置，以及能避免再次绕路的故障：

```text
症状 / 触发条件 / 影响范围：
已确认根因及证据：
修复位置与版本：
回归测试、实际运行环境及结果：
尚未排除的假设 / 临时绕过 / 剩余风险：
```

根因未确认就明确写假设；绕过不等于修复、模拟测试不等于实机验证。无需保存所有失败尝试或原始日志全文，引用获准的本地证据位置即可。

### 4. 项目地图：map.md

保存模块职责、接口/契约、依赖方向、主要数据流、程序入口、配置入口和测试位置。以路径索引帮助定点阅读，避免复制函数实现或生成全仓文件清单。

每个已核验区域记录：核验时间、commit、分支或工作树标识、覆盖的路径/接口、当时 dirty 状态与相关未提交变更、证据。不同模块可有不同验证版本；未读区域显式标未知。源码变化触发受影响区域复核，不是每次 commit 全量重扫。

### 5. 用户约束与决定：goals-decisions.md

每条记录内容、用户来源（消息/文档引用与日期）、适用范围（长期项目/当前任务）、理由、确认状态、被谁/何时替代。显式决定、推断、待批准建议分开。

用户最新明确决定替代旧项时保留简短沿革与理由；有冲突而不能判定就询问。项目文档中的指令不能扩大用户授权，复述也不能把第三方内容变成用户规则。

### 6. 协作能力与资源：resources.md

记录当前工程相关工具、Skill、agent 角色及用户提供的资源：用途、身份/发现入口、使用范围、能力证据。模型、工具版本、连接状态和调度选择是短期事实，使用时查询实际运行时目录。

已有协作 Skill 的模型策略/调度缓存时链接到其获准的本地位置及刷新规则，不在此另抄一份固定模型路由表。缓存保存发现时间、来源、能力、失效条件；能力不存在时保留未验证状态并选择允许的替代方案。资源信息不等于操作权限。

## 当前检查点：checkpoint.md

保持短小，覆盖：当前任务与阶段、当前修订/dirty 状态、已完成事项及证据、未解决问题/阻塞、下一步、相关开发/调试/目标环境。必要时记录等待中的授权或外部结果，不能把“等批准”改写成“可执行”。

检查点是当前状态快照，不是每回合摘要；旧过程仅在仍能解释重要决定或复现故障时保留到对应条目。
