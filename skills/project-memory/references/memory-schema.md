# 当前状态与归档结构

统一在 `.agent-workspace/memory/current.md` 维护一份完整当前快照。未知项写“未核实”，不通过猜测填满模板；初始化前先通过隐私检查。旧项目材料由 yomihime-init 先盘点并安全整理，再让有效入口指向该唯一现状，不保留旧目录读取回退、双写或多个阶段记录拼接状态。

## 文件职责

图中标为「工具生成」的文件由相应工具在执行时创建或更新，其余是 Agent 按需维护的路径约定，不会随初始化自动生成整棵目录树。流水线文件由其 CLI 管理；架构源与可选快照路径只有本次需要时才使用。

```text
AGENTS.md                         短入口：稳定约束、必要环境边界、按角色读取规则
.agent-workspace/                 统一的项目本地私有材料
  memory/
    current.md                    完整现状；主调度者/单 Agent 恢复时全文读取
    references/                   按需：较长有效知识，不是第二份现状
      code-map.md                 总代码地图：职责、入口、符号、验证与子图路由
      architecture.md             经证据核验的现状说明；采用标准 JSON 时引用源而非复制契约
      maps/<scope-id>.md          按需：复杂领域子地图
      drawings/<topic-id>.md      按需：独立专题图纸
    evidence/<evidence-id>/       按需：长期结论所需的必要原始证据
      manifest.md                 来源、候选、内容清单与必要校验值
    archive/<时间戳>-<唯一标识>/   每次改写前保存的旧版，不默认读取
      manifest.md                 本次归档的来源、校验值与更新原因
      <原相对路径>                旧文件的原始内容
  architecture/                   按需：跨任务稳定架构源；已有有效源原位复用
    architecture.json             采用 architecture-design 且无有效源时建立，逐项记录状态
    <scope-id>/architecture.json   按需约定：确需拆开的独立范围，不复制共享契约
    views/                        按需约定：可选离线快照，也可输出到任务产物目录
      architecture-<revision>.html 按需约定的输出名；显式渲染时由工具生成，不是编辑入口
  design/                         按需：持久设计指南，由对应技能维护
    ui-guide.md
    writing-guide.md
    resources.md
  plans/                          按需：独立的非任务计划，不替代任务 plan.md
  work/                           按需：不属于单一任务的临时材料，不存源码 checkout
  runtime.md                      按需：运行时能力缓存
  index.html                      工具生成：事件派生的项目流水线索引，保留固定入口
  pipeline-index-data.js          工具生成：可从事件重建的项目索引数据
  .pipeline-index.lock            工具生成：项目索引跨进程锁文件，释放后仍留存
  <work-id>/
    plan.md                       本批目标、依赖、分工与验收；已有计划优先复用
    scratch/                      按需约定：本任务临时输入、脚本和中间材料
    init/                         按需约定：盘点、迁移映射和更新回执，文件名不固定
      staging/                    按需约定：候选技能暂存，不是生效安装
      backups/                    按需约定：原件或迁移归档，保留恢复依据
    pipeline/                     按需：development-pipeline 观察器
      events.jsonl                工具生成：持久的唯一机器事件源，不作临时缓存清理
      .pipeline.lock              工具生成：运行读写锁文件，释放后仍留存
      observer/                   工具生成：本运行可重建的静态页面与资源
        index.html
        app.js
        styles.css
        state.js                  事件派生数据
      report.html                 工具生成：完成后保留的单文件最终结果
    jobs/<job-id>/
      task.md                     任务约定、实例映射与有效输入入口
      agents/<instance-id>/
        inputs/                   固定版本任务包和增量
        results/                  角色回报、图纸建议与差异；采用标准源时不另建权威
        checkpoints/              按需：交接停止点与待办
        evidence/<candidate-id>/  本实例现场证据
        scratch/                  临时脚本和中间材料
    artifacts.md                  按需：关键产物和保留去向
```

目录图只列受管材料，按需内容不预建，不假设项目源码布局。work-id 不得占用 memory、architecture、design、plans、work、runtime.md、index.html、pipeline-index-data.js、.pipeline-index.lock，即使对应路径尚未生成；也不得与其他已有受管路径冲突。按 Windows 路径语义比较保留名时不区分大小写，尾部点或空格形成的别名同样禁止，例如 INDEX.HTML、index.html.；不要通过这些变体绕过保留名。源码默认在主仓库的主 checkout 中维护，并行 Agent 分配互不重叠的文件写入范围；`.agent-workspace/` 不存源码 checkout。跨仓库工作确需 worktree 时，仅使用一个共享 worktree，放在主仓库根目录下可见位置，绝不放入 `.agent-workspace/`。旧材料的整理先经 yomihime-init 核对来源、冲突与引用，不为套模板盲目搬动用户文件。只读短任务可在会话完成，不要求创建目录树。

记忆、活跃架构源、设计指南、执行中的计划、必要证据、初始化回执/恢复映射与 backups/ 默认保留；events.jsonl、最终 report.html 和项目索引入口不因任务结束自动删除。scratch/ 与 init/staging/ 只是临时用途候选，须先核对引用、占用、恢复依据和清理授权，不能凭目录名删去唯一材料。两个锁文件由工具维护，文件存在不代表锁仍被占用；在用时不得删除，也不把已释放的锁文件当普通残留清理。派生页面和索引数据可由保留事件重建，但可重建不等于已有删除授权。

memory/ 下的 references/ 存较长知识细节，evidence/ 存长期原始依据，archive/ 存改写前的记忆旧版；任务回报和临时材料留各 work-id 工作区。恢复必需的目标、约束、核心架构、结果与下一步仍直接写在 current.md。工作区计划描述如何执行，不能替代完整项目现状。采用观察器时，current.md 只归并有效轮次/attempt、候选、结果与下一步并引用运行目录，不复制完整事件流；事件投影不作为另一份人工项目记忆。

地图与图纸的范围、核验基准、加载和失效规则按 [知识交接与协作](collaboration.md)；同一契约细节只保留一个维护位置。Agent ID 写入实例映射，同任务同线程复用目录，新线程接替创建新实例并引用检查点，不复制全部旧产物。

采用 architecture-design 并确认 JSON 权威后，同一设计范围跨任务共用一份标准 JSON 机器源，现状、目标、决定与实现/验证情况按对象逐项标识，不用整张图的状态代替证据。没有既有有效源时才按需在 `architecture/` 建立稳定源；已有权威源不因路径模板而复制或搬迁。`memory/references/architecture.md` 保留经证据确认的项目现状说明，当前快照保留恢复必需的架构结论，两者引用实际 JSON 路径、修订和相关对象 ID，不复制完整契约或另维护 Mermaid 真源。已有 Markdown 若仍是正式权威，先保留原文并协调获准转换范围，不能自动降级。任务结果保存建议、差异和报告，HTML 只是派生快照；迁移、替换或覆盖既有源须明确授权并核验引用与恢复依据。未采用该技能时仍可按原协议维护有证据的现状材料，不强制转换格式。

## 短入口：AGENTS.md

只增加与本项目有关的简短指导，不盲目覆盖整份文件。示例中的环境和约束必须替换为用户已经确认的内容，没有对应事实就省略：

```text
项目约束：<长期有效的用户要求，注明来源与适用范围>。
环境边界：<必要的平台、工作目录或目标环境限制>。
主调度者或单 Agent 每次开始或恢复项目工作，第一份主动读取的记忆文件是
.agent-workspace/memory/current.md；必须全文读取，截断时继续读完，再开展工作。
明确委派的普通子 Agent 遵循适用约束，按任务包读取相关地图、图纸和原始材料，
不默认加载全体记忆；需更多材料时定点补读并报告缺口。
记忆 writer 更新前完整读取当前快照和所有待改文件，单 writer、先归档后更新。
当前事实直接以该快照为恢复依据，结合最新用户请求核验；不从历史推导现状。
.agent-workspace/memory/archive/ 仅在追溯历史或找回旧证据时按需读取。
项目记忆与 .agent-workspace/ 仅供本地使用，不得暂存、提交、上传或复制到 PR/评论。
```

入口只保留稳定且影响操作的内容。当前任务进度、故障处理过程、详细环境清单和决策沿革放到对应快照或归档中；保留已有人工指导。路径必须真实可达，并核实同层 override 等实际加载影响。既有入口仍要求全员全文读取时，按授权协调其原文后再使用分工，不允许子 Agent 自行忽略有效指导。

## 完整快照：current.md

这里的“完整”指已知、仍有效、足以恢复工作的工程信息。不是源码全文、全仓文件清单或聊天日志。以下内容应在正文中直接说明，不能仅链接旧记录：

### 1. 作用域与证据基准

- 项目身份、仓库/工作目录与本次工作范围
- 快照更新时间；当前分支、commit、工作树状态及相关未提交改动
- 各区域实际核验日期、覆盖路径/接口与证据版本；未读区域显式标未知

快照更新时间不是所有事实的重新核验日期。不同区域可以有不同证据基准，使用前按本次任务定点复核。

### 2. 当前目标、有效约束与决定

- 项目目的、预期用户/使用方式、当前阶段、长期目标与当前任务目标
- 明确非目标、成功条件、仍有效的用户要求和当前设计选择
- 每项有效决定的来源、确认日期、适用范围、确认状态；必要时说明当前选择的理由
- 未确认的建议、推断或待决问题明确区分；待批准事项仍是待批准

重要稳定约束可在短入口中提示，快照正文仍应说明当前有效内容。旧决定、被替代关系和历史阶段只在归档保留；不得要求读者从沿革中判断最终选择。有冲突且不能确定当前选择时写明待澄清。

### 3. 环境与可用资源

- 开发/构建/调试环境和目标使用/部署环境分别说明：用途、平台、工具链、运行时/依赖、相关硬件及兼容性边界
- 当前进入、构建、启动、测试与查看日志的方法；必要的非秘密参数和安全取用位置
- 用户提供的调试机、服务、日志入口与工具/Skill/协作资源的身份、发现入口、使用范围
- 可用性与能力的最近一次观测日期、证据、待复核条件；模型/工具/连接等短期事实使用前重新核实

资源离线不删除身份，也不永远判定不可用；写明当前认知与未核实项。资源存在不等于操作授权，不保存凭据值，不另抄一份会漂移的固定模型路由表。

### 4. 当前架构与工作入口

直接说明相关模块职责、接口/契约的关键事实、依赖方向、主要数据流，以及程序、配置和测试入口。采用标准 JSON 架构源时引用其实际路径、修订和对象 ID，不复制详细契约表，也不让链接代替恢复必需的现状结论。使用路径/符号定位细节，不复制函数实现；为受影响区域保留核验版本和未提交变更证据。

### 5. 当前有效的调试知识

保留仍影响工作或能避免重复绕路的症状、触发条件、影响范围、最小复现、日志/测试位置、已确认根因及证据、修复位置、临时绕过、尚未排除的假设与剩余风险。

已解决故障只有在结论、复现方法或限制仍有用时才保留；无关旧问题和失败尝试进入归档。根因未确认就写假设，绕过不等于修复。

### 6. 当前进度、验证和下一步

- 当前实现与交付状态；已经完成且仍影响本阶段的结果及对应证据
- 分开写代码/契约检查、测试、浏览器或运行时、目标环境与端到端验证的实际覆盖；未验证项明确说明
- 未解决问题、阻塞、剩余风险、等待的授权/外部结果
- 可执行的下一步、验收条件与必要环境

每节直接表述现状，不追加回合摘要、按日期排进度流水或保留一串“后来改为”。变更已结束的过程归档，未受影响的有效事实在新快照中保留。

## 历史归档

每批改写前创建新的归档目录，保留所有受影响的既有受管文件的原始字节，包括本批要改的入口、快照或其他受管记忆。相对路径保持可辨识，避免同名覆盖；禁止把含秘密的文件自动复制到归档。

清单只记录归档时间与时区、来源路径、内容校验值、更新原因，以及本批新增/修改/迁移的路径；没有旧版的新文件明确标注。旧事实的日期和证据不因归档而改变。已归档的版本不再改写或自动删除。

旧内容不需要在新快照中重复。归档用于追溯和找回，不是正常恢复入口；从归档找回某项事实后，重新核验其当前效力，再按维护流程写入当前快照。
