# 当前状态与归档结构

默认采用一份完整当前快照。未知项写“未核实”，不通过猜测填满模板；初始化前先通过隐私检查。已有兼容布局可以保留路径名，但必须让有效入口明确指向唯一完整现状，不能继续用多个阶段记录拼接状态。

## 文件职责

```text
AGENTS.md                         短入口：稳定约束、必要环境边界、全文读取指令
.project-memory/
  current.md                      完整当前状态；每次开始或恢复时首先全文读取
  archive/<时间戳>-<唯一标识>/     每次改写前保存的旧版，不默认读取
    manifest.md                   本次归档的来源、校验值与更新原因
    <原相对路径>                  旧文件的原始内容
```

仅当确有需要时保留额外参考，存放原始证据或较长实现细节。它们不是另一份当前状态，也不能藏着恢复所必需的有效目标、约束、结果或下一步。

## 短入口：AGENTS.md

只增加与本项目有关的简短指导，不盲目覆盖整份文件。示例中的环境和约束必须替换为用户已经确认的内容，没有对应事实就省略：

```text
项目约束：<长期有效的用户要求，注明来源与适用范围>。
环境边界：<必要的平台、工作目录或目标环境限制>。
每次开始或恢复本项目工作，第一份主动读取的记忆文件是
.project-memory/current.md；必须全文读取，截断时继续读完，再开展工作。
当前事实直接以该快照为恢复依据，结合最新用户请求核验；不从历史推导现状。
.project-memory/archive/ 仅在追溯历史或找回旧证据时按需读取。
这些记忆文件仅供本地使用，不得暂存、提交、上传或复制到 PR/评论。
```

入口只保留稳定且影响操作的内容。当前任务进度、故障处理过程、详细环境清单和决策沿革放到对应快照或归档中；保留已有人工指导。路径必须真实可达，并核实同层 override 等实际加载影响。

## 完整快照：current.md

这里的“完整”指已知、仍有效、足以恢复工作的工程信息。不是源码全文、全仓文件清单或聊天日志。以下内容应在正文中直接说明，不能仅链接旧记录：

### 1. 作用域与证据基准

- 项目身份、仓库/工作目录与本次工作范围
- 快照更新时间；当前分支、commit、工作树状态及相关未提交改动
- 各区域实际核验日期、覆盖路径/接口与证据版本；未读区域显式标未知

快照更新时间不是所有事实的重新核验日期。不同区域可以有不同证据基准，使用前按本次任务定点复核。

### 2. 当前目标、有效约束与决定

- 项目目的、预期用户/使用方式、当前阶段、长期目标与当前任务目标
- 明确非目标、成功条件、仍有效的用户要求和当前设计选择
- 每项有效决定的来源、确认日期、适用范围、确认状态；必要时说明当前选择的理由
- 未确认的建议、推断或待决问题明确区分；待批准事项仍是待批准

重要稳定约束可在短入口中提示，快照正文仍应说明当前有效内容。旧决定、被替代关系和历史阶段只在归档保留；不得要求读者从沿革中判断最终选择。有冲突且不能确定当前选择时写明待澄清。

### 3. 环境与可用资源

- 开发/构建/调试环境和目标使用/部署环境分别说明：用途、平台、工具链、运行时/依赖、相关硬件及兼容性边界
- 当前进入、构建、启动、测试与查看日志的方法；必要的非秘密参数和安全取用位置
- 用户提供的调试机、服务、日志入口与工具/Skill/协作资源的身份、发现入口、使用范围
- 可用性与能力的最近一次观测日期、证据、待复核条件；模型/工具/连接等短期事实使用前重新核实

资源离线不删除身份，也不永远判定不可用；写明当前认知与未核实项。资源存在不等于操作授权，不保存凭据值，不另抄一份会漂移的固定模型路由表。

### 4. 当前架构与工作入口

直接说明相关模块职责、接口/契约、依赖方向、主要数据流，以及程序、配置和测试入口。使用路径/符号定位细节，不复制函数实现；为受影响区域保留核验版本和未提交变更证据。

### 5. 当前有效的调试知识

保留仍影响工作或能避免重复绕路的症状、触发条件、影响范围、最小复现、日志/测试位置、已确认根因及证据、修复位置、临时绕过、尚未排除的假设与剩余风险。

已解决故障只有在结论、复现方法或限制仍有用时才保留；无关旧问题和失败尝试进入归档。根因未确认就写假设，绕过不等于修复。

### 6. 当前进度、验证和下一步

- 当前实现与交付状态；已经完成且仍影响本阶段的结果及对应证据
- 分开写代码/契约检查、测试、浏览器或运行时、目标环境与端到端验证的实际覆盖；未验证项明确说明
- 未解决问题、阻塞、剩余风险、等待的授权/外部结果
- 可执行的下一步、验收条件与必要环境

每节直接表述现状，不追加回合摘要、按日期排进度流水或保留一串“后来改为”。变更已结束的过程归档，未受影响的有效事实在新快照中保留。

## 历史归档

每批改写前创建新的归档目录，保留所有受影响的既有受管文件的原始字节，包括本批要改的入口、快照或其他受管记忆。相对路径保持可辨识，避免同名覆盖；禁止把含秘密的文件自动复制到归档。

清单只记录归档时间与时区、来源路径、内容校验值、更新原因，以及本批新增/修改/迁移的路径；没有旧版的新文件明确标注。旧事实的日期和证据不因归档而改变。已归档的版本不再改写或自动删除。

旧内容不需要在新快照中重复。归档用于追溯和找回，不是正常恢复入口；从归档找回某项事实后，重新核验其当前效力，再按维护流程写入当前快照。
