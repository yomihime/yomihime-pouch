# 隐私与真实加载链

## 写入前：先确定文件身份，后决定内容

1. 确认仓库根、当前目录、worktree、实际 Git 元数据位置；不要假设 `.git` 是目录。列出适用的祖先/子目录 `AGENTS.md`、`AGENTS.override.md` 与客户端真实配置中的备用文件名。只检查已获准读取的配置，不探索凭据或改全局配置。
2. 先用路径级 Git 检查区分 tracked、staged、新文件、ignored，以及已有人的内容；避免把整个文件或 diff 打进日志。检查目标路径是否为符号链接或指向共享位置，不能借链接写到范围外。
3. 确定私有目录，例如 `.project-memory/`，只是候选名称，不得覆盖同名既有目录。现有可用结构优先，不为了套模板重排用户文档。
4. 写入模式先保护全部本次管理的未跟踪私有路径，包括已经存在的入口/记忆和即将新建的文件；不能只排除新文件。用 `git rev-parse --git-path info/exclude` 得到本地排除文件路径；保留原内容，增加精确、根相对、正确转义的排除项，避免排除无关文件。根入口示例为 `/AGENTS.md`、`/AGENTS.override.md`、`/.project-memory/`。有嵌套私有入口时添加它的准确路径。随后用 `git check-ignore` 和 `git ls-files` 验证；不能把 `--no-index` 的忽略结果当成“未被追踪”。只读检查不能追加 exclude。
5. already tracked/staged 的文件不会因 exclude 消失。若私有记忆或入口已经在索引里，报告路径/状态和隐私冲突，停止发布它；不得自行 `git rm --cached`、改用户暂存区、删除文件、历史重写或用 override 偷偷绕过。即使看似不含密钥，也不能默认可提交。

## AGENTS.md 的作用域

依据 [Codex 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)（核验日期：2026-10-03），Codex 每次运行构建一次指导链：全局层，再从项目根到工作目录逐层加载。每层选择 `AGENTS.override.md`，没有才选 `AGENTS.md`，之后才考虑已配置的 fallback 名称。同目录 override 替代该层 AGENTS 的选择，不是追加。实际版本、配置和字节预算以当前运行环境为准。

- 已有 override 时，不能声称新写 AGENTS 一定生效；确认有效入口及其人写内容后再提出最小修改。
- 已有共享 tracked AGENTS 时，保留它，不自行改成私有或创建 override 将其遮蔽。说明冲突，选择已获授权的本地方案；若没有，询问用户要保留共享指导并在会话中显式读取独立本地记忆，还是采用其他经确认的布局。不要复制共享指导来制造一个会漂移的影子副本。
- 存在嵌套规则时按当前任务路径判断作用域；仅在指导确实不同且获得授权时增加嵌套入口。不要为每个目录自动生成。
- 新文件、链接或本轮修改不代表当前运行已经重新加载。当前会话显式读取必要私有文件；下次运行需核实指导链与预算。不要宣称链接的参考被自动加载。

## 发布前：只允许明确清单

本地记忆保护必须覆盖 Git 之外的渠道：PR 描述、评论、打包/构建 manifest、上传目录以及给其他 agent 的提示词均不得夹带实际私有文档或秘密值。

同项目、同授权边界内的本地子 agent 可按任务选择读取所需私有文件；只交付必要的本地路径与读取范围，不自动把文件全文拷进任务提示词，不向其他机器或外部 agent 上传。先检查敏感性并最小化读取；若文件混有密钥，不让子 agent 直接读出值，也不为恢复而复制秘密。无法安全选择必要内容时保留阻塞并请求安全的本地处理方案。

- 列出全部 staged 路径与拟发布路径，逐一对照本次通用代码/Skill 的允许清单；避免 `git add .`、`git add -A` 或递归上传整个工程目录。
- 若用户原有暂存项含私有入口/记忆，不得用一次全索引提交发布；不调整原索引。可在独立 worktree 或显式 API 文件清单中继续通用变更，但必须再次确认发布内容没有那些文件。
- 对允许清单做最终 diff 审查和常规敏感信息检查；审查输出只给安全摘要，不打印命中的值。路径排除和字符串扫描都不保证无泄露，还要核对内容来源。
- 发布 Skill 只带手写通用策略/模板和合成测试，不带实际项目记忆、从真实文件脱敏复制出的样本或真实环境快照。
