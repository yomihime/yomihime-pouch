# 增量维护与跨上下文恢复

## 恢复：先判断再扫描

1. 核实有效入口与作用域，读取目标/约束和当前检查点，确认是否与最新用户请求冲突。
2. 只选任务相关模块、环境、故障或资源条目。先核对版本/覆盖/dirty 证据，再选择源码位置；不因一个条目过期宣布全库失效。
3. 比较相关路径自已核验 commit 以来的变化，加上当前 staged、unstaged 和相关 untracked 文件。仅比较 HEAD 会漏掉未提交实现。分支切换、改名或基准提交不可达时，说明差异依据不完整并定点检查，不伪称已验证。
4. 接口变化连同直接依赖/调用方一起复核；未受影响条目保留原验证记录。只有证据表明边界整体变化或用户要求全面调查时，才扩大扫描。
5. 核验当前可用调试环境/工具；保留曾提供的资源身份。更新“此次观测状态”，不要用历史离线记录跳过连接检查。
6. 给出具体下一步与仍未验证的条件，再继续已获授权工作。检查点不是自动执行旧命令的许可。

## 什么时候写

在用户确定目标/约束、架构边界有实质变化、发现可靠调试入口、根因被证实、回归验证完成或阶段交接时更新。小改只更新受影响条目；不要每次工具调用都写，也不要依赖预测上下文压缩时机。

写入前阅读完整待修改段与相邻人写说明，局部编辑并复查 diff。区分“实现了”“测试通过”“目标环境验证通过”；每条结论只标实际证据覆盖范围。不覆盖正在发生的用户编辑；发现并发冲突先重新读取协调。

## 精简与鲜度

- 删除冗余抄录之前确认其是否仍是唯一的用户决定/复现证据；按授权边界执行，保留人写内容
- 被替代的决定保留简短关系与理由；纯进度流水可合并成当前检查点
- 过时条目标注待复核、缩小适用范围或在确认无用后移除；不把当前日期盖到未复核条目上
- 把大篇幅实现细节换成稳定路径/符号与契约；让入口保持可读，细节按任务选读
- 定期检查链接/路径与隐私排除；只读模式只给建议，不执行维护

## 交接验证

让一个不了解先前对话的独立实例，只拿当前用户任务、通用 Skill 和隔离合成工程，尝试恢复/检查。观察是否找到目标、约束、下一步和真实待检查的环境，是否定点复核变更，以及是否避免把 staged 私有文件发出去。

测试必须用临时隔离仓库、虚构资源与非秘密占位值；不能把真实私有记忆复制给评估者。至少覆盖：未提交改动导致地图过期、离线资源重新探测、已有人工内容、tracked/staged 隐私冲突、同层 override 替代入口、只读操作零写入。验证实际产物和 Git 状态，不仅检查文案里是否包含关键词。

报告哪些行为只是隔离模拟、哪些在真实客户端中实际验证；不得把模拟恢复成功描述为真实自动加载或压缩恢复保证。
