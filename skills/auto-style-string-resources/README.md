# auto-style-string-resources

这是一个 Codex 技能，用来审计和改进项目中的用户可见文字，包括 UI 字串、i18n 资源、README 和 docs。它适用于中文、日文等多语言项目，也能帮助定位硬编码文案。

技能会先核对文字的使用场景和项目风格，整理场景树，给出 `style_score`、处理等级及改写示例，再按用户授权的范围分批修改。目标是清楚自然地表达，而不是套用固定话术；事实、真实警告、限制、不确定性、占位符和程序契约都要保留。`style_score` 表示风格发挥空间，不是自然度评分，也不代表修改许可。

## 风格选择

可根据用户偏好和项目现有语气，选择或组合“实用简洁”“清晰引导”“轻松自然”“主题化表达”“日系轻柔”，也可以自定义。各场景的表达强度可以不同，警告和错误始终以准确清楚为先。中文和日文分别按各自的习惯和场景斟酌，不因选用预设自动翻译或同步其他 locale，也不强加人设。

## 项目风格指南

项目本地规范与中间产物统一放在 `.agent-workspace/`：文案指南是 `.agent-workspace/design/writing-guide.md`，临时树和候选表放在 `.agent-workspace/<work-id>/scratch/`；`design/` 同目录的 `ui-guide.md` 和 `resources.md` 可按需使用，不默认生成重复规则。先从适用的 `AGENTS.md` 查找简短入口，再在统一工作区内定向查找，包括可能被忽略的目录。已有指南由 `yomihime-init` 盘点并安全整理，保留内容、不自动覆盖；冲突先报告并确认，不建立旧路径长期兼容或第二份指南。找到后只读取与当前工作相关的部分并核对实际文案，不重复全仓扫描。没有指南时，先分析并提出精简内容；创建或更新须在用户授权范围内。只有授权后才在 `AGENTS.md` 添加简短路径入口，保留原有内容，并说明指南缺失时参考现有文案并提示用户。

当前指南作为持久参考保留；完成后只清理本次明确可清理的自建临时材料。已有文件不自动覆盖；有具体证据表明风格或约束实质变化时，再提出或按授权局部更新。`.agent-workspace/` 默认本地、不默认提交或发布；被 Git 忽略或未跟踪的指南可能不会随克隆传播，分享前确认授权与隐私，不写入密钥或不必要的敏感信息。保留用户已有共享约定；用户明确要求的正式文档或发布产物按指定位置交付，不强制私有化。

## 文件

- `SKILL.md`：技能的主入口。
- `scripts/draft_string_tree.py`：从特定目录和部分 Python 字串生成启发式草稿，不覆盖所有框架、资源或文档，也可能收录技术字串，需要人工核对和补查。
- `scripts/check_string_constraints.py`：检查常见占位符、路径和格式约束，但不验证位置参数的顺序，不能替代语义和运行时核对。
- `agents/openai.yaml`：技能界面元数据。

## 安装

把整个目录复制到 Codex skills 目录：

```text
~/.codex/skills/auto-style-string-resources/
```

使用示例：

```text
使用 $auto-style-string-resources，审计当前项目的 UI 文案和 README，整理场景树并给出低风险改写候选。
```

## 运行条件与触发边界

可选扫描与约束脚本仅用标准库，完整扫描能力需要 Python 3.8+；目标源码语法还必须能被当前解释器解析。 具体触发正反例、平台限制与实测范围见 [SKILL.md](SKILL.md#触发示例与运行要求)。

扫描器支持 `i18n/*.json` / `*.jsonl` 和 `gui/`、`core/`、`utils/` 中的 Python 初筛。CLI 退出码为 0（完整，包括有效空项目）、1（部分成功，只输出成功文件）、2（根目录错误或全部失败）；stderr 保留诊断与统计。JSONL 坏行会报告行号并拒绝整个文件，不把部分结果伪装成完整扫描。范围外资源仍需另查。
