# 多 Agent 工程协作

用户调用 Skill 的对话是主调度者，对完整目标与获准交付负责。入口模型由用户选择，只能给出建议。角色表示职责，按需启动，可有多个同类实例；子任务完成不等于整体交付。

采用 development-pipeline 时，接收其需求、里程碑、切片、依赖层次、顺序轮次、检查点与验收范围。同轮独立任务按容量并行，跨轮等待前轮任务与检查点满足；失败按主调度者决定返回指定轮次，不是固定返修次数。没有该 Skill 时仍可直接按依赖协调，不要求额外安装。

## 边界与启动

- 遵循有效项目指导和最新用户要求，区分要求、已有行为、建议与待证假设。明确本轮是调查、计划还是实现，以及允许的路径和外部动作；角色和记忆不增加权限。
- 有 project-memory 时由主调度者完整恢复唯一当前快照，再定点核对本次范围。子任务按下方任务包加载；不把主线程历史、全部记忆和全仓调查作为每个角色的启动材料。已有入口要求更广读取时先协调有效指导，不自行忽略。
- 保留用户改动、暂存区、真实配置、数据和私有材料。提交、推送、安装、发布和清理按实际授权执行，避免把内部返修变成逐次续批。
- 先确认实际委派能力和容量。出现就绪且值得委派的独立工作时使用真实子 Agent；短任务可由主调度者完成。无委派工具时顺序履行职责并如实说明未完成独立审查。

## 角色

| 角色 | 主要责任 | 边界 |
| --- | --- | --- |
| 主调度者 coordinator | 目标、任务依赖、分工、写入权、冲突裁决、结果接收和整体交付 | 全局决定负责人，可委派整理和实际文件写入 |
| 实现者 implementer | 在切片范围写代码、必要测试、自检和返修 | 按切片并行，不擅改公共契约 |
| 架构师 architect | 模块、接口、依赖、状态所有权、现状图纸与集成边界 | 重大边界变化时参与，不逐项审批普通实现 |
| 设计师 designer | UI、视觉、交互状态和必要设计资产 | 无视觉任务无需启动；实现与资产范围分开分配 |
| 顾问 consultant | 对疑难问题、冲突证据、反复返工提供根因和方案判断 | 按明确问题介入，通常只读；不代替该方案的独立审查 |
| 测试员 tester | 执行用例与断言，汇报原始结果和覆盖缺口 | 不默默修产品代码后宣称独立通过 |
| 审查官 reviewer | 对照需求、候选和原始证据独立验收 | 未参与该候选方案与实现的新上下文 |
| 交互验证员 interaction-validator | 观察真实界面、执行获准流程、核对实际结果 | 按需；截图不等于业务成功 |
| 记忆维护员 memory-maintainer | 归并已接收事实、维护地图和检查点、归档与更新回执 | 按需且计入并发；不代替专业角色裁决技术事实 |
| 工作区整理员 cleaner | 盘点产物、检查引用占用、归档和已授权清理 | 按需；范围和恢复依据明确后操作，不按名称猜可删 |

设计师执行视觉任务时，若运行时可用则加载 `ui-design` Skill，并按任务读取项目设计规范及相关设计系统、组件和现有界面上下文。规范或 Skill 缺失时说明缺口，依据可用需求、平台约束和现有界面继续设计；不为此安装 Skill 或强制加载无关 Skill。

调查随任务归属交给相应角色，不额外凑齐常驻岗位。低风险职责可合并，独立审查不得由候选作者或参与该方案者冒充。

## 可开工任务包

委派前按 [任务包与通信](references/task-cards.md) 提供目标/验收、有效约束、候选、工作目录、写入与资源范围、依赖和相关地图/图纸入口。只交付必要事实与可访问来源，标明已知、假设和未知。

实现者取得任务和足够的相关地图/契约后即可从准确入口读代码开工；地图不替代编辑前核对实际文件。测试员还需环境与断言，交互验证员需真实页面及操作授权，审查官需稳定候选和原始证据，维护员需完整待改文件，整理员需精确清单与授权，顾问需具体问题和失败证据。

启动只核对本任务必需条件，不等完整项目测绘或所有角色准备完成。缺口按任务标记，定点补读或询问；能独立推进的授权工作继续。地图缺失时做有边界的调查并回报入口，不反复扫描全仓。

## 并行、通信与交付

- 以主仓库主 checkout 为源码工作的共同位置，在有效轮次和检查点约束内维护任务依赖并调度就绪切片；未采用有序流水线时可按依赖直接推进。并行实现者取得互不重叠的文件写入范围；共享文件和接口语义指定唯一 owner，必要改动由其完成或先交回写入权再移交。页面、数据库、端口和构建目录也需协调。跨仓库任务确需额外 worktree 时，仅设一个所有相关角色共享、位于主仓库根目录下可见位置的 worktree，不放入 `.agent-work/`。
- 同一任务追问、补证和返修优先复用原 Agent，只发增量。新任务不沿用无关历史；新 Agent、模型交接和独立审查采用聚焦新上下文，保留任务检查点。主线程继承不等于继承另一个子 Agent 的历史。
- 技术澄清可点对点，使用任务/输入版本和候选标识。公共契约、权限、范围或验收变化交主调度者协调并通知受影响角色；直接消息不能转移写入权或悄悄创建新决定。
- 测试和审查绑定稳定、可标识的实际候选，包含相关未提交文件。修复后按影响重验；可复用证据说明原候选、变化范围和复用依据，不把旧通过自动覆盖新版。
- 审查意见含位置、影响、证据及 Blocker / Important / Polish。Blocker/Important 未闭合不交付该候选；组织诊断、修复和相关复验，继续不受影响工作。重复返工或无进展时请顾问，不机械重试，不自行制造固定轮数或时间上限。
- 汇报需求、实现/候选、证据及状态，保留 passed / failed / skipped / unrun。源码、模拟、真实运行和目标环境分开；不得将任务包、启用标记或截图当作端到端成功。
