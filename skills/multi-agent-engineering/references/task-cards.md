# 最小任务卡与证据

卡片可以放在已有计划或会话中。只保留有执行价值的字段，不要求为每个字段另建文档。

```text
TASK-01 / 角色与专业范围：
目标、REQ ID、非目标：
委派理由 / 独立产物 / 复用或新开 agent：
基线修订 / 必要事实 / 可访问的原始来源（路径、符号、链接）：
风险 / 歧义 / 所需能力：
输入依赖与就绪条件：
允许动作 / 唯一写入范围 / 只读范围：
预期产物、验收和必需证据：
模型 / effort / speed / 生效配置证据或未知：
预算：总尝试、上下文规模、并发；费用/用量实测或未知
升级/停止条件：
回报：结论/阻塞、改动/位置、验证状态与证据位置、未完成项/下一步
```

共享契约由主协调者分配单一 owner。两张卡都“只改各自 worktree”但修改同一接口语义，仍然冲突。先串行确定契约，再释放并行任务。

同一任务补充或修复时只传新增事实、变更范围与当前修订，优先复用原 agent；新任务或独立审查使用聚焦的新上下文。任务卡给足可执行条件，其余通过来源按需读取，不附整段历史或日志。证据路径须在接收方可读；仅作者机器可见的路径不算完成交接。

## 需求与证据链

```text
REQ-01：来源类别 + 需求 + 验收
实现：路径/符号/提交
验证：命令或操作 + 环境 + 修订 + 原始结果位置
状态：已实现 / 已验证 / 待验 / 阻塞 / 获准延期
缺口：原因 + 责任方/下一步
```

失败输出不要只截取最后的“成功”摘要。测试不能运行记 `unrun`；主动跳过记 `skipped` 并给原因；执行失败记 `failed`；`passed` 仅用于实际完成且满足断言的检查。mock 成功不能关闭真实服务或真机验收。

## 审查与交接

reviewer 使用未参与方案与实现的新上下文，收到需求、稳定修订、相关原始材料及可访问的证据位置；先独立形成判断，再对照 implementer 说明和既有审查项，不能只复述作者自评或前次结论。每项意见含严重级别、文件/行为位置、影响及证据，主协调者记录「采纳 / 拒绝及依据 / 经授权延期」。存在争议时复现或比较需求，不按意见数量投票。

验收发生在修订 A、修复写入 B 后，A 的结果仍是历史证据，不自动覆盖 B。交接写清当前修订、已知事实、仍待证假设、占用的写入权、剩余预算与阻塞，完成或中止后释放写入权。

## 临时会诊卡（仅触发时补充）

沿用任务卡，补充「待裁决问题、候选方案及约束、已尝试修订与失败证据、剩余预算」。请求专家给出根因或方案取舍、证据、不确定性与最小验证建议；不要求重复实现或替代最终审查。无剩余预算时先报告阻塞并申请，不借会诊启动第三轮修复。
