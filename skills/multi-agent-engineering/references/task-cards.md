# 可开工任务包、通信与证据

本协议名为 task-handoff-v1。任务包可写在会话或已有计划，只有交接、版本或产物确需持久化时才落盘。主调度者维护有效任务版本，不为每个字段另建文档。

## 下发任务包

```text
protocol: task-handoff-v1
identity: work-id / job-id / instance-id / input-version / role
pipeline: 按需关联 REQ、milestone、slice、layer、round/wave、检查点、运行目录/节点 ID、本任务验收与证据
goal: REQ 来源、目标、非目标、预期产物、可观察验收
constraints: 有效用户要求、权限与数据边界、不得改变的行为
baseline: 主仓库与主 checkout 绝对路径、候选、相关 staged/unstaged/untracked 基准；跨仓库确需共享 worktree 时另列其可见路径与原因
knowledge: 相关已核验事实、来源与范围；假设和未知分开
maps: 相关地图/图纸路径与章节/符号、基准、现状或目标及确认状态
architecture: 可选；稳定入口、唯一架构源路径/章节、修订/基准、现状或目标与确认状态、本任务范围、writer/交接接收者；按需引用视图与契约，不复制另一份图源
dependencies: 已就绪契约版本、输入、上游/下游任务；未就绪项
access: 可读范围、互不重叠的文件写入范围、共享文件和资源 owner、允许动作
outputs: 报告与证据位置、所需验证、停止/交接条件
resources: 已知模型/effort/速度及生效证据或未知、容量与用户硬限制
```

字段按任务取舍，但目标、验收、约束、基线、操作范围和角色必需材料不能省略。精确路径/符号加必要事实通常足够，不默认附整个对话、全部地图、全仓文件或日志。地图不是路径白名单：允许为当前问题补读必要直接依赖，但不得借补读扩大写入或数据权限。

architecture 是可选产物引用，不改变 task-handoff-v1 的必需条件，也不要求额外文件或安装 `architecture-design`；已有 maps/计划能准确承载时直接复用。引用须区分已核验现状、目标方案与待证假设，架构视图不能代替代码和运行证据。跨任务图纸复用现有有效源；无源时才按需使用 `.agent-workspace/architecture/`，由已有 `AGENTS.md` 或 `memory/current.md` 入口指向同一源，不另造 project-memory 副本。交接核对入口可访问、修订与状态一致、writer 已移交，并列出必须保留的图源、仍被引用的依据和视图；清理任务目录不得删除它们，不擅自迁移或覆盖。

pipeline 是可选关联信息，不改变 task-handoff-v1 的必需条件；未采用流水线时可省略。采用时交本任务的轮次准入、检查点、切片、前置和验收，不复制全局历史；按派发的节点上报事件并将简短摘要同步主调度者。切片自检、检查点、集成验收和整体交付结论分开，不能从 JOB 完成推导整轮通过。

若 project-memory 提供了带来源的知识摘录，复用其快照/地图基准和覆盖说明；协调者将它与本次要求、权限和候选合并成任务包，不让子 Agent 自行从历史猜约束。任务包不是新权限来源；有效 AGENTS/override 等指导仍须遵循。

## 启动确认与缺口

接收者用一条简短消息确认任务/输入版本、候选、实际工作目录与写入范围，报告 ready 或 gap；没有问题即可工作，不强制等待协调者再次批准。发现过期路径、候选不符、未定义接口或材料不可读，明确指出缺的内容和影响。

- 可自行解决的缺口：从准确入口读实际文件和必要调用方，核对相关未提交变化，补齐本任务需要的事实并回报。
- 影响正确性或权限的缺口：提出一个具体问题，暂停受影响操作；其他独立授权工作继续。未知输入不能猜成确认契约。
- 地图缺失/过期：针对本任务补充调查或请求对应角色补图，不把完整全仓测绘设为启动门槛。新模块首次设计也可先依据需求、约束和已有边界工作。

## 角色必需输入与加载范围

| 角色 | 任务和相关地图/图纸之外的必需材料 | 默认避免 |
| --- | --- | --- |
| 实现者 | 精确代码入口、已就绪契约、写入权；编辑前读取实际文件与必要直接依赖 | 其他切片全文、无关历史 |
| 架构师 | 目标/非目标、约束与关键质量属性、受影响接口/状态所有权/不变量、代码证据与现状/目标差异；已有架构产物和待决问题按需提供；可用时加载 `architecture-design`，新领域允许有界调查 | 未受影响实现细节、全仓强制扫描和无关 Skill；缺技能或图纸时标缺口并按现有证据继续，不自行安装 |
| 设计师 | 用户场景、平台/组件约束、已有画面或状态；按需读取项目设计规范、设计系统与相关组件；可用时加载 `ui-design` Skill，新界面可从需求起稿 | 后端全仓、无关日志、无关 Skill；缺少设计规范或 `ui-design` 时说明缺口并按可用上下文继续，不自行安装 |
| 测试员 | 稳定候选、环境/数据隔离、命令或用例与断言、原始结果位置 | 作者“应该通过”的自评 |
| 交互验证员 | 实际页面/应用与会话身份、步骤和期望结果、允许副作用、证据位置 | 大量无关截图和实现全文 |
| 审查官 | 原始需求、正式契约、稳定候选与差异、相关原始证据 | 作者自评、上一轮通过或预设审查答案 |
| 顾问 | 具体难题、候选方案与约束、已尝试假设、必要源码和失败证据 | 完整项目历史和未经核验的根因断言 |
| 记忆维护员 | 完整待改文件、已接收事实批次、原始证据、基线校验值、写入范围 | 产品代码全仓和未经接收的结论 |
| cleaner | 准确目录/产物清单、引用/占用、保留与恢复要求、整理或删除授权 | 根据名称、时间自动判断价值 |

## 点对点通信

消息只发给实际受影响的角色。短事实澄清可直接互通，涉及接口、依赖、权限、候选或结论变化时同步主调度者。长材料给可读路径和关键片段，避免全员广播和日志搬运。

```text
kind: question / fact / interface-change / blocker / result / cancel
from-to: 角色或 Agent ID；关联 job-id / input-version / candidate
content: 一个具体问题、新事实或变化；来源与证据位置
impact: 影响的契约版本、任务、写入或资源；与既有决定是否冲突
action: 请求谁回答/裁决、建议下一步或无需动作
```

消息引用旧输入时先核对当前任务版本。公共契约先由 owner 与协调者确认新版本，再更新受影响任务包；受影响角色确认新版本后继续相关写入，未受影响任务照常推进。不把直接回复或地图建议自动升级为用户要求。取消/改范围后核对在途工具和残留改动，不以发出消息等同于执行已停止。

## 回报与需求证据链

先回报结论/阻塞，再给任务与输入版本、实际候选、改动/产物、执行状态和原始证据、事实/假设/建议、剩余问题与下一步、写入权及资源状态。长日志留在证据位置，保留必要失败片段；不能只报“完成”或一个链接。

```text
REQ 来源与验收 → 实现路径/符号及实际候选
验证：命令/操作、环境、断言、passed / failed / skipped / unrun、证据
状态：已实现 / 已验证 / 待验 / 阻塞 / 获准延期
新知识：范围、事实与来源、已排除假设及依据、待证项、应复核地图
```

未实际运行是 unrun，主动跳过是 skipped 并给原因，执行不满足断言是 failed。生成脚本、静态检查、mock、真实运行及目标环境分别报告。主调度者接收报告后确认采用的事实与当前决定，再归并项目记忆；报告本身不等于全局决定。

## 同任务复用、新 Agent 接替和独立审查

同任务补证/返修优先原 Agent，仅补增量与新基线。需要新线程或换模型时交接：候选与目录、已读路径/符号、契约、事实证据、排除依据、待证项、具体停止点和下一步、未提交改动、在途操作与资源。接替者核对后开始，不重放全历史，也不声称无损恢复。

最终审查官使用未参与该候选方案与实现的新上下文，先独立看需求、候选和原始材料，再对照作者说明。复审具体问题时提供问题与变更差异，但旧候选通过不覆盖新候选。审查项须给位置、影响和证据；争议按需求和复现裁决，不按人数投票。

会诊使用同一协议，额外聚焦一个待裁决问题、候选方案、已尝试内容和明确硬限制；不让顾问重复全仓调查，不默认设修复轮数或续批次数。
