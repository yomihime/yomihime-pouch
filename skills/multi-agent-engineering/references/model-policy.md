# 按实际运行时生成模型安排

Skill 提供选型依据，不保存永久角色→型号路由或中央模型目录。主调度者结合任务、运行时与账户、用户约束生成工程安排；只缓存本地必要发现，不回写成分发 Skill 或全局配置。

## 发现与生效值

优先复用已有有效发现，按实际提供的接口、选择器、配置或官方文档确认可用模型、工具、effort 和速度。只调用确实存在且获准的命令，不编造 list-models，不批量发起付费推理探测。公开目录不证明账户可用，本会话不证明另一运行时可用。

缓存可在获准的 .agent-work/runtime.md 或已有工程私有位置，记录来源/时间、环境账户范围（不存秘密）、配置版本、候选能力、覆盖关系、计量来源与未知项、失效条件。只读任务只在会话或获准临时空间保留。工程缓存和单任务选择分开，单次覆盖不改长期规则。

发现不完整时仅在已确认候选或当前继承模型中选择，标未知；必要能力确实不足才报告缺口。自定义 Agent 配置可能覆盖请求，启动后按可见元数据核对；不能核验时写“请求值已知，实际值未知”。不自动改配置来获得模型，也不假称运行中热切换。

主对话模型由用户决定。子 Agent 使用新上下文或继承、模型/effort 覆盖的组合限制按当前工具核对，不将某个产品的规则套到其他产品。

## 先能力门槛，再成本取舍

1. 先检查用户/组织允许模型、provider、数据去向、权限、总预算与期限等硬约束。
2. 判断任务风险、歧义、跨层状态、图像/工具要求、上下文和证据责任，选择能胜任的候选。
3. 再按软偏好选择模型、effort、速度和必要并行程度；验收标准不随档位降低。

| 档位 | 取舍 |
| --- | --- |
| economy | 快速候选处理明确盘点、既有测试执行与事实整理；复杂实现、契约和关键审查匹配足够能力，优先减少重复上下文与返修 |
| balanced | 对关键路径和歧义适度提前使用较强能力，独立部分按资源并行 |
| quality | 更重视复杂推理和交叉证据，仍受用户与平台硬限制约束 |

不将 economy 固定成两个人或少开人：真正独立的切片可并行，计入交接、重复调查、工具、重验和返修后的总成本。并发遵循实际容量与用户约束，未指定时不制造固定轮数、时间窗口或逐次续批额度。

能力与 effort 分开，角色与型号分开，速度/服务等级另记。不默认额外付费加速；接口固定或继承的参数如实报告。高 effort 不能自动弥补能力或资料缺口，强模型也不总需要最高 effort。

## 候选示意

当前官方定位可作为起点：Luna 用于明确高频工作；Sol 用于复杂工程和关键判断；Terra 可用于视觉、界面操作、写作和范围明确的修复；Astra 可用于明确的疑难瓶颈。相同角色可按任务用不同候选，不以型号代替职责或能力验证。

偏性价比的起点可评估：实现/架构/审查 Sol-medium，高风险 Sol-high；视觉设计与交互验证 Terra-medium；已有测试执行和记忆/清单整理 Luna-medium；疑难顾问按必要能力考虑 Astra。这里只是候选示意，需账户可用、参数支持和任务验证，不能据此创建整套团队。

## 开销、失败与调整

有真实 token/费用/延迟才记录实测；无遥测写未知，可观察输入规模、重复读码、重建次数、就绪等待和返修。不编造货币估算，不用 API 单价换算订阅额度；严格金额上限需要运行时可执行保障，不能仅凭提示词承诺。

普通失败先分清权限、环境、工具、网络、上下文、契约或模型能力。权限拒绝不能靠换模型绕过，缺少地图可定点调查，环境坏了先修环境。复杂歧义、反复返工或无进展时按具体问题请顾问，而非机械重试或无条件升级。

相关环境、账户、配置变化、候选不可用或缓存失效时刷新发现；不每个任务查全目录。用户改变硬限制时在安全可行处暂停/取消相关工作，检查在途副作用，保存检查点，不等旧任务完成才处理。

更换模型在接口支持的任务边界执行，或向新 Agent 交接当前事实、候选与停止点。超出用户明确模型、费用、数据或权限边界时取得必要决定；边界内普通调整不逐次续批。没有合格候选则保留阻塞，不能悄悄降验收标准。
