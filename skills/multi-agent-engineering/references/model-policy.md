# 在工程内部生成调度规则

Skill 只提供生成策略与模板，不保存权威角色→型号路由或中央模型目录。主协调者结合工程事实、实际运行时、用户预算与质量门槛，在当前工程内生成并缓存调度规则；禁止把某次生成结果写回分发的 Skill 或全局配置。

## 1. 发现目标运行时，建立一次快照

首次委派前先确认任务实际在哪里运行、用哪个账户/服务。读取该运行时**已提供**的模型发现接口、模型选择器、配置或官方文档；只调用确实存在且获准的工具/命令，不编造 `list-models` 一类命令，也不批量发起付费推理探测。

优先复用工程已有调度/缓存约定；否则放在工程本地忽略的工作区（例如 `.codex/work/<project-id>/scheduling/`，只加本地 exclude）。只读任务未获写入权限时仅在会话或获准临时空间保留，不能借“缓存”改工程。工程缓存与逐任务决定分开：前者保存候选、约束和生成规则，后者记录本轮选型与临时覆盖；单次覆盖不静默改长期策略。缓存以下最小信息：来源与时间、适用环境/账户范围（不存秘密）、运行时/配置版本、可用模型 ID、能力及可选 effort/speed、角色配置和覆盖关系、已知费率/用量来源、仍未知的字段、生成规则版本及失效条件/复查时点。公开目录只证明产品信息，不能证明账户可用；本会话可用也不能证明目标运行时可用。

若无法发现完整目录，仅在已确认可用的模型/当前继承模型内调度，标明未知；无法满足必要能力或硬约束时先询问/报告阻塞。不要猜一个名字后反复重试。自定义 agent TOML 中显式 `model` 可能覆盖 spawn 的选择，必须检查实际生效配置；启动后按可见元数据核对，不能核验就标「请求值已知，实际值未知」。不自动修改配置来获得想要的模型。

## 2. 先过硬约束，再选最小胜任模型

对每张任务卡按顺序评估：

1. 用户/组织的模型允许或禁止列表、provider、数据去向、权限、总预算及截止时间。任何一项不满足就不能选。
2. 正确性门槛：风险、歧义、跨层依赖、所需工具/图像能力、上下文量、测试与证据责任。选择**满足门槛的最小模型**，不是无条件最便宜。
3. 在合格候选中按用户的软偏好取舍。未指定时说明采用保守预算假设，并在工程生成规则中选择合适档位；用户要求高质量或更快时调整。

| 软档位 | 调度取舍 |
| --- | --- |
| economy | 清单/机械任务优先轻量，复杂判断留给强模型；可将同时最多 2 个子任务、standard speed 作为工程生成规则的保守起点，按约束确认 |
| balanced | 对歧义与关键路径适度提前使用强模型，独立部分按预算并行 |
| quality | 更重视复杂推理、交叉证据和关键审查，仍受硬预算与能力边界约束 |

档位不改变验收标准。高 effort 不会把弱模型变成强模型；强模型也不必一律最高 effort。只选择运行时实际支持的值，继承的上层固定设置优先，不虚称已切换。speed/service tier 与模型、effort 分别记录；不擅自启用额外付费加速。

## 3. 控制总体开销，而非只看单次价格

- 开工前设任务总尝试/重试次数、总上下文输入规模、并发上限和检查点。根据任务卡设数值，不用无上限的“直到成功”。两轮修复预算包含失败尝试，拆子任务不能重置总上限。
- 委派最少必要上下文，交接传结论、来源和待办，不复制整段对话。保留独立 reviewer 所需原始材料，不能为省上下文只给它自己的结论。
- 有实际 token/费用/延迟遥测才记录实测；没有就写未知，用次数、输入规模等可观察代理约束。没有费率或计量不编造货币估计；订阅额度/消耗不能直接用 API 单价换算。
- 提示词不能强制硬金额上限。需要严格上限时确认运行时是否有可执行限额；已知下一步将超限就停，不能确认可守住用户硬上限时在继续前说明限制并取得决定。预算用尽不降标准，报告未完成项。
- 普通失败先区分权限、环境、工具、网络、缺失上下文与模型能力。权限拒绝不能靠换模型绕过，构建环境坏了也不是升级模型的理由。

## 4. 刷新与升级

目录在运行时、账户、配置/版本变化，模型不可用或缓存明显过期时刷新；不要每个子任务重新查询。策略在用户明确更改预算/风险，或持续观察到质量不足时调整，并记录依据和生成规则版本；观察到成功或失败都不能改写用户硬约束，变更它们必须由用户明确授权。新模型仅进入候选集合，不因发布就全局替换。

活动任务通常固定模型，但硬约束变更优先于固定模型：用户撤销许可、收紧数据边界或新增硬预算导致当前运行可能越界时，立即在安全可行处暂停/取消，不等完整任务结束；保留检查点，核对已发生/仍在运行的副作用，不盲目重试。需要改模型时，在任务边界或保存检查点后交接；记录旧/新选择、证据及剩余预算。工具不支持运行中切换时不要假称热切换。昂贵或超出既有授权的升级先请求同意；无合格候选则阻塞，而不是偷偷突破约束。

## 工程生成记录示意

```text
project-policy: 工程标识 / 规则版本 / 生成时间
inputs: 用户硬约束与软偏好来源 / 风险与验收基线
catalog: 来源 / 时间 / 目标运行时与账户范围 / 配置版本
validity: 复查时点 / 失效条件
routing: 能力门槛 → 当前合格候选 → 选择依据（工程生成）
limits: 总尝试 / 上下文 / 并发 / 已知计量及未知项
task-decision: TASK ID / policy version / 本次选择 / 生效值 / 临时覆盖与理由
```

这只是字段模板。不要将当前会话的清单或桌面音频示例复制成所有工程的默认规则。
