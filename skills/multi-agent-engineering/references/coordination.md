# 动态调度、工作区与产物

## 容量与任务连续性

分别发现活跃执行容量、打开线程上限和计数方式；主线程是否计入以实际接口为准。有效容量受平台和用户约束，不写死两个或三个子任务，也不把累计创建数当同时活跃数。已有有效发现可复用，不为每个子任务重新探测。

维护任务依赖和就绪队列，按关键路径、风险、资源冲突和上下文重建代价调度。不采用轮次流水线时，切片输入就绪即可开工，完成即可接入下游；采用 development-pipeline 时还必须遵守已开放轮次和检查点，不能绕过轮次屏障。同轮独立实现可多实例并行，角色表不是必开清单。子 Agent 如需继续拆分先向主调度者请求，统一计量，避免递归开团队。

同一切片连续实现与返修尽量交回原 Agent。短期待补证可保留线程上下文并释放不再使用的写入权；闲置是否占线程额度必须核对。不按任意时间片强制轮换，不永久预留空的顾问/审查/记忆槽位。新领域、独立审查、能力变化或上下文混杂时再交接新线程。

结果已接收且无后续职责、任务取消或上下文不适用时保存检查点，按接口能力停止或关闭。中断、关闭线程、释放写入权和删除产物是不同动作；后台进程可能仍在运行。无关闭工具时报告停止/交接状态，不声称线程已销毁或额度已释放。

## 只展示受管路径

项目本地材料统一使用 .agent-workspace，下列路径按需生成，不创建空模板树，不覆盖既有内容。旧项目材料由 yomihime-init 在下次开工时先盘点，再按授权安全整理，不设旧目录回退或双写。AGENTS.md 保留人工指导，tracked/override 冲突按 project-memory 或当前有效指导处理。未采用 project-memory 时不强制创建记忆目录。

```text
AGENTS.md
.agent-workspace/
  memory/                           采用 project-memory 时由其管理
    current.md
    references/                     按需：总地图、图纸和领域细节
    evidence/<evidence-id>/          按需：长期必要证据
    archive/<archive-id>/            记忆改写旧版
  design/                           按需：UI、文案和资源持久指南
  architecture/                     按需：无现有有效源时新建的跨任务架构唯一源与派生视图
  plans/                            按需：独立的非任务计划，不替代任务 plan.md
  work/                             按需：不属于单一任务的临时材料，不存源码 checkout
  runtime.md                        按需：运行时发现和调度缓存
  index.html                        按需：事件派生的项目流水线索引
  <work-id>/
    plan.md                         本批目标、依赖、分工与验收
    pipeline/                       按需：使用流水线观察器时
      events.jsonl                  机器事件源；网页与状态由此投影
      .pipeline.lock                跨进程读写锁，不手动删除在用锁
      observer/                     本运行的预制静态页面
        index.html
        app.js
        styles.css
        state.js                    事件派生数据，原子更新
      report.html                   完成后：单文件最终报告
    jobs/<job-id>/
      task.md                       任务约定与实例入口
      agents/<instance-id>/
        inputs/                     固定版本任务包与增量
        results/                    回报、建议差异等任务中间材料
        checkpoints/                按需：接替检查点
        evidence/<candidate-id>/    日志与截图等现场材料
        scratch/                    临时脚本和中间材料
    artifacts.md                    按需：关键产物与去向
```

work-id 标识工作批次，避免与 memory、design、architecture、plans、work 及已有受管文件重名；job-id 标识可交付任务，instance-id 关联真实 Agent ID。相同线程继续同任务复用目录；新线程接替创建新实例并引用必要旧材料，保留失败证据，不复制整个旧目录。无落盘产物的短任务可在会话处理。

主调度者维护分工和有效任务版本。所有源码默认在主仓库的主 checkout 直接修改；并行实例的源码文件写入范围互不重叠，共享文件、地图与记忆指定唯一 writer，需要转交时先收回原写入权。实例目录仅存中间输入、回报、检查点、现场证据和临时材料，不是源码 checkout 或最终交付位置。已有适用计划优先复用，不制造同内容多份计划。current.md 直接说明项目现状，计划说明本批怎么做，原始回报与运行时缓存都不成为第二份项目现状。

采用流水线时，一个任务失败会停止新增工作和下游放行，其他已在途任务仍须回报真实结果。主调度者在失败决策、顾问或阻塞期间继续接收其终态、候选和证据，先接收已完成结果再返回；取消/交接的未完成任务说明实际停止点，不用统一重置掩盖结果。

不要为每个 Agent 或切片创建 worktree。只有跨仓库工作确有必要时才创建一个共享 worktree，放在主仓库根目录下的可见位置，绝不放入 `.agent-workspace/`；相关角色共享该 worktree，仍按不重叠文件范围分配写入权。先确认实际路径、仓库、分支、授权与既有内容，避免覆盖用户文件。目录隔离不是权限沙箱。明确命令工作目录、源码写入范围、分支/候选、相关 dirty 文件如何进入候选及集成负责人。页面、数据库、端口、构建和临时目录单独分配；测试和审查读取冻结的真实候选，不在仍被改写的目录上声称验收稳定。

AGENTS.md、实际项目记忆、工作区和路由缓存本地私有。写入前保护本次未跟踪私有路径，使用准确本地 exclude；不改共享 .gitignore、不取消跟踪用户文件。发布按明确文件清单核对，不能靠 ignore 保证不泄露，也不把真实材料塞进通用 Skill。

## 信息与脚本的去向

- 正式代码、资产、文档和可维护工具沿用工程既有位置与写入分工，不把临时记录混入交付。
- 子 Agent 回报必要结论与证据入口，长日志不反复复制到聊天、快照和新任务包。简短判断不用另造 Markdown。
- 有效工程事实及代码入口经接收后归并记忆。采用 architecture-design 且已确认 JSON 为唯一权威源时，现状与目标由同一长期 JSON 图源以 current/planned/proposed/unknown 区分，任务结果只存建议、差异与报告，不另存权威目标图纸；未采用时也先复用已有有效图源，尚未纳入的建议可留任务结果，不冒充现状。先从稳定入口定位既有源并原位复用；无源且确有需要时才按需新建 `.agent-workspace/architecture/`，不擅自迁移或覆盖。
- 临时脚本先复用既有命令与工具，确有复现或重复操作需要再创建。说明用途、输入输出、允许副作用、执行状态；长期保留时由实现者参数化、验证并放正式工具位置，不能依赖私有工作区。
- 当前快照或验收长期引用的必要证据先按 project-memory 协议固化到稳定位置，保留源映射与核验；未关闭引用或恢复缺口前不清理源文件。

架构图源在已有 `AGENTS.md` 或 `memory/current.md` 登记同一稳定入口、修订、现状/目标状态与 owner；已确认 JSON 为唯一权威源时，memory 的架构文档只保留已核验摘要和指向该源的引用，不维护同义副本，current.md 仍直接保留恢复必需概览。若既有 memory/正式架构文档本身仍是权威，则保留并先协调唯一权威与获准的格式转换，不能直接降为摘要或旁建第二图源。交接检查入口可读和修订一致，并确认接收者及唯一 writer；图源与仍被引用的依据/视图不属于 jobs、scratch 或 pipeline 的普通清理范围。

产物登记可复用任务卡或一份 artifacts.md：路径、用途、生成者、任务/候选、执行状态、引用/占用、接收者及去向。只登记关键产物，单 writer 汇总；不为每个再生缓存建账和哈希。

## 维护员与 cleaner

记忆维护员收到完整待改文件、已接收事实批次、必要证据和写入范围后按 project-memory 流程归档、更新、回读，返回实际纳入项与校验回执；不擅裁决产品或技术争议。它计入正常容量，短更新可由主调度者处理。

实例先成功交接并由主调度者接收结果、必要证据和写入权，再按运行时能力回收该 Agent；确认它及其后台进程不再使用材料后，才将其实例目录列为清理候选。无法确认回收或停止时保留目录并报告，不以回收本身代替删除授权。Cleaner 在阶段接收或收束时盘点精确路径、用途、大小、引用/占用、保留要求和恢复证明。先输出保留、归档、临时或待核实分类，再按已有授权的精确批次操作；无删除授权则只交清单，不影响其他工作。小任务可由维护员兼任，职责与权限仍分别明确。

迁移/归档前验证稳定副本、原路径映射和引用可达性。文件变化、清单外路径、占用、未知来源、拒绝或验证失败时跳过并报告，不按名称、日期、大小或“废弃”标签猜可删，不改 ACL 绕过拒绝。未提交源码、真实数据与凭据、唯一复现、未完成验收证据和记忆 archive/ 不在普通临时清理范围。

worktree 退役核对分支、使用者和 dirty/untracked 内容；角色退出不授权递归删除。清理回报实际路径、核验、跳过项与残留资源；移动、逻辑删除、回收站变化及物理释放分别报告。保留仍被历史材料引用的证据或可核验恢复办法。
