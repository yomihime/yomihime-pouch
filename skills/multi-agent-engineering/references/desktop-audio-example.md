# 示例：保留 UI 的桌面音频包装

情境用于解释能力与证据分层，不是已完成项目、已确认 bug 或永久型号配置。候选只有在账户可用、工具和参数支持、用户边界允许时采用；不要把示例复制成所有工程规则。

已有客户端第一阶段用 Electron 或 Tauri 包装并保留原 UI，调查输入设备问题；重写 UI 属于后续另行确定范围。当前地图应给设备选择、采集、发送和跨进程生命周期的准确入口；未知关系标明后定向调查，不让每个实现者重扫整个客户端。

| 职责 | 偏性价比候选示意 | 必需输入 |
| --- | --- | --- |
| 架构师 | Sol-medium；跨进程竞态按风险考虑 high | 模块/进程边界、设备入口、状态契约与必要代码 |
| 设计师/交互验证员 | Terra-medium，按需分工 | 当前 UI/实际运行时、状态与允许操作，验证需真实设备与流程 |
| 实现者 | Sol-medium；生命周期 high；机械修改可评估 Luna | 明确切片、已就绪契约、入口和写入范围 |
| 测试员 | Luna-medium 执行已确认用例 | 稳定候选、实际环境、用例与断言 |
| 审查官 | 新上下文 Sol，effort 匹配风险 | 需求、候选与差异、相关原始证据 |
| 顾问 | 需要时选择胜任的强推理候选 | 具体难题、已尝试假设与失败证据 |

按实际容量并行架构调查、界面准备或已有行为检查。接口就绪后独立切片可并行，稳定切片可先测试；同一切片返修回原 Agent。无 UI 变化不强行开设计任务，不为示例固定并发数或续批次数。

deviceId 约束丢失、semaphore 未释放、mute 与采集状态耦合只是待证假设。先定位并记录实际轨道与状态，再决定修复，不为了合理猜测全部修改。

按实际设备与系统验证：

- OS 默认输入 A、客户端选 B：请求 deviceId、实际 track settings 与实际采集结果一致，不能只看下拉框文字。
- 权限失败后重试：无永久锁死、重复采集或错误残留。
- 拔插、切换、重启：恢复行为、轨道关闭与资源释放符合确认契约。
- mute/unmute：按产品定义核对采集、发送和 UI，不预设必须停止麦克风。
- 实际打包运行时：核对权限、启动退出和 sidecar 生命周期；开发浏览器只提供部分证据。

没有真实设备或目标 OS，相关用例记 unrun，交接具体操作；源码或 mock 通过不能声称设备问题已彻底解决。原始日志和必要截图留实例证据目录，长期结论所需材料再固化，避免整段输出进入每个 Agent 上下文。
